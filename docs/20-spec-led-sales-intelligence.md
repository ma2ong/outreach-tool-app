# Spec 20 — LED 销售雷达、可解释评分与采购信号

> 状态：Implemented / Verified
> 日期：2026-08-12
> 对应：Doc 14 Wave R + Wave S

## 1. 要解决的问题

当前 `target_fit` 只回答“官网看起来像哪类 LED 买家”，不能回答业务员每天真正要问的三个问题：

1. **今天先跟谁？** 高契合但没有联系人，和已回复、已报价的客户不能只按同一个 ICP 分排序。
2. **为什么现在联系？** 项目、招聘、展会、经销品牌、招标或官网变化必须保留证据，不能凭空个性化。
3. **下一步做什么？** 分数必须落到找决策人、回复、确认规格、跟报价或建商机等具体动作。

## 2. 设计原则

- **总分必须可解释。** 展示 ICP、联系人、意向、互动、数据时效五个分项及加减分理由。
- **证据先于判断。** 每条采购信号必须有来源 URL、证据原文/摘要、抓取时间和可信度。
- **低可信信号不自动触达。** 系统只排序和建议，任何发送仍经过现有人工发送门禁。
- **一个行动入口。** 信号可一键转为销售任务或商机，进入已有任务/商机事实来源。
- **不复制 CRM 数据。** 分数实时读取联系人、触达、回复、任务、商机、报价和信号，不另存容易过期的总分。

## 3. 可解释销售优先级（0–100）

| 分项 | 上限 | 业务含义 |
|---|---:|---|
| ICP 契合度 | 30 | 现有官网分类分按 30% 折算 |
| 联系人质量 | 20 | 有姓名、决策角色、可用且验证过的渠道 |
| 采购意向 | 25 | 新鲜且高可信的信号，或已经形成的商机阶段 |
| 互动进展 | 15 | 已触达、重复互动、客户回复 |
| 数据时效 | 10 | 官网、国家、简介/开场白、联系方式和复检状态 |

等级：A ≥ 75，B ≥ 55，C ≥ 35，D < 35。`do_not_contact`、已赢单、已丢单不进入开发优先队列。

## 4. 下一最佳动作优先级

1. 不再联系 / 已成交 / 已丢单边界；
2. 未处理回复、逾期任务；
3. 已接受报价转订单、已发送报价跟进；
4. 高可信新信号的建议切入点；
5. 现有商机下一步；
6. 补决策人、修复无效邮箱或寻找可用渠道；
7. 基于官网证据进行首次触达。

## 5. 采购信号模型

`buying_signals`：

- `signal_type`：project / hiring / exhibition / distributor / tender / social / site_change / location / partnership / manual
- `headline`、`evidence`、`source_url`
- `occurred_at`、`captured_at`、`confidence`（1–100）
- `use_case`：Rental / Fixed Installation / DOOH / Retail / Sports / Church / Control Room / Broadcast / Virtual Production
- `product_fit`、`suggested_angle`
- `status`：new / reviewed / actioned / dismissed
- `opportunity_id`：已转商机时关联
- `fingerprint`：同一证据幂等，避免复检和重复录入制造噪声

官网复检发现真实变化时写入 `site_change` 信号；首次存量回填不制造信号。

## 6. 用户界面

新增“销售雷达”页面：

- 顶部卡片：A 级优先客户、新采购信号、缺决策人、数据待补全；
- 客户优先级表：总分、五个分项、关键理由、下一最佳动作；
- LED 采购信号台：证据、来源、可信度、建议切入点；
- 人工录入信号；
- 信号一键转任务、转商机或忽略。

## 7. 验收标准

- 任一客户总分可追溯到五个分项和具体理由；
- 无来源 URL 或无证据的信号不能保存；
- 同一信号重复录入不产生重复行；
- 低可信信号不自动发送、不自动建商机；
- 信号转任务/商机幂等，并完整关联原客户和证据；
- 官网复检变化写入有来源的信号，首次回填不写；
- 真实数据库迁移、后端全量测试、生产构建和浏览器验收全部通过。

## 8. 明确边界

- 本轮建立可信信号的数据结构、官网变化入口和人工录入入口；招标网站、展会名录、LinkedIn/社媒的自动采集器应按国家与来源逐个接入，不能用一个泛爬虫宣称“全网意图”。
- 分数用于安排销售注意力，不代表成交概率；成交概率仍属于具体商机。
- 系统不会根据分数或信号自动发送消息。
