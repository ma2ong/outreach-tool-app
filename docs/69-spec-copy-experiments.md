＃ 69 — 话术是实验，不是一个总数

## "361 封 1 个回复" 指导不了任何决定

这是今天能看到的全部信息。它把**四个市场、五种客户类型、三个步骤、两个语言**压成了一个数字。
0.3% 到底是因为：

- 开场白写得不好？
- 名单不对？
- 第一封还行，是第二三封在耗？
- 对美国有效、对韩国无效？

看这个数字答不出来，所以每次调整都是猜。今天换角度二也是猜——**有根据的猜，但仍然是猜**。

## R1 每封信记下它是哪一场实验

`send_log` 已经有 `campaign`，但那是一个自由文本。追加四个字段：

| 字段 | 例 | 为什么 |
|---|---|---|
| `variant` | `英语·角度二` | 哪一套话术 |
| `step` | `0` | 第几封。第一封和第三封是完全不同的东西 |
| `audience` | `租赁商` | 哪种客户。同一句话对租赁商和工程商效果不同 |
| `market` | `USA` | 哪个市场 |

四个都从发送时已经拿在手上的数据里取，不需要新的判断。

## R2 回复归到"这个客户在哪一场实验里"

一次回复不属于某一封信，属于**一段接触**。第三封发出后收到回复，不代表第三封的功劳——
前两封铺了路。

所以口径定死一条：**回复归给这个客户在这条渠道上最近一次的 variant**。它不完美，但它稳定，
而且换角度的那一刻界线清楚：换之后收到的回复算新角度的。

## R3 分流而不是全量切换

今天把 110 个跟进一次性全转到角度二。如果角度二更差，要一个月后才看得出来，而那一个月的
名单已经烧掉了。

以后新话术**先分一半**。两个角度并行跑够样本再定。

分流的判据用 `lead_no % 2`——稳定、可复现、不需要额外存储，同一个客户不会今天在 A 明天在 B。

## R4 不做自动淘汰

这个业务的样本天然小：一个市场一个月几十封。让程序按显著性自动关掉一个角度，**比让 Allen
看着表决定更容易出错**——他知道那 30 封发的是什么客户，程序不知道。

系统的职责是把表摆出来：哪个角度、哪个市场、哪种客户、第几封、发了多少、回了多少。

## R5 历史数据不回填

现有的 637 条 `send_log` 没有这四个字段，也无法可靠地补：当时的客户类型可能已经变了，
序列名也被改过。**空着就是空着**（[45 号 spec](45-spec-truthful-lead-facts.md)），报表从
有记录的那天开始算。

## 不做的事

- 不改 `campaign` 字段，它还有别的地方在用
- 不做多臂老虎机之类的自动分配。先能看清楚，再谈优化
- 不给社媒私信分流。它一天十几条，样本量撑不起两个角度

## 验收

1. 一封序列邮件发出后，`send_log` 里能看到 variant / step / audience / market
2. 报表能回答"角度二在美国租赁商上的回复率"
3. 新话术上线后，同一批客户里一半走旧角度一半走新角度
4. 同一个客户不会在两个角度之间跳来跳去
5. 历史记录这四个字段是空的，报表不把它们算成 0
