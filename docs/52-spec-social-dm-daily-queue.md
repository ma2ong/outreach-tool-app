# 52 — 社媒私信：Agent 备好，Allen 一键发

## 为什么现在要做

`AGENTS.md` 的规则没有改，也不会改：

> Never auto-start a new WhatsApp/Instagram/Facebook conversation.

理由和当初一样，而且代码里就留着证据——`channel_outreach.py` 顶上写着
`exceeding ~20 got the WhatsApp account rate-limited (2026-05-15)`。邮件发砸了换个域名
养回来；Instagram 发砸了账号没了，WhatsApp 发砸了那个绑着微信和全部客户联系方式的
手机号没了。这类损失不可恢复，所以按下发送的那一下必须是人。

但规则的本意是"人来承担这个风险决定"，实际效果却成了"没人做，渠道死掉"：

| | |
|---|---|
| 有 Instagram 的客户 | 518 家 |
| 有 Facebook 的客户 | 373 家 |
| 有电话（WhatsApp）的客户 | 724 家 |
| 社媒最近一次发送 | **2026-07-23**，一个多月前 |

发送能力是完整的：浏览器引擎、资格过滤、日上限、限速、模板、案例图，全都在。**闲置的
不是能力，是那段没人愿意每天重复做的准备工作**——从九百多家里挑出今天该发谁、按什么
顺序、每条写什么。

所以这份 spec 不解除那条规则，它把规则**两侧**的工作分开：准备全部自动，发送仍然是人
点的那一下。

## 规则

### R1 队列是 Agent 每天备好的，发送始终是人点的

Agent 每天生成一份"今日社媒私信"队列：选客户、定渠道、写正文，落进
`social_dm_queue` 待确认。它不发送，也不能发送——这张表里没有任何东西会被
自动执行。Allen 打开、逐条看、改或删掉不想发的，然后按发送。

发送本身仍然走 `channel_outreach.send_channel_campaign`，因为日上限、资格过滤、
do-not-contact、每公司限次和案例图都长在那条路上。这里不复制一份。

### R2 节奏要像人，不是像满负荷的机器

平台不数你发了多少条，它看你像不像人。一个脚本每天准点发满 40 条，是最容易被认出来
的模式之一。所以配额本身是随机的：

- 每天每个渠道 **8–15 条之间随机**（不是固定值，也不是原来的日上限 40/40/20）
- Facebook 取区间下半段：三个渠道里它对冷私信封得最狠
- 队列的生成时刻随机落在上午的一段窗口里，不是每天同一分钟
- 周末减半——真人周末不会照常群发陌生私信

发送间隔沿用 `DEFAULT_DELAY`（WhatsApp 60–90 秒、Instagram 120–240、Facebook
150–300），它已经是踩过限流之后调出来的。

### R3 一家公司同一天只出现在一个渠道里

同一家客户今天既收到 WhatsApp 又收到 Instagram 私信，从对方看是骚扰，从平台看是
批量行为。一家公司一天只进一条队列，渠道按"哪个联系方式更可靠"决定。

已经在邮件序列里今天要被触达的客户，也不进社媒队列——[45 号 spec](45-spec-truthful-lead-facts.md)
之后我们才刚把"同一批客户被塞进两个序列"的事收拾干净。

### R4 排在前面的是最值得发的那几家

八到十五条是很小的配额，所以顺序就是全部价值。排序依据，从强到弱：

1. 有买信号的（`buying_signals` 里有未过期的记录）
2. ICP 分数
3. 有 `hook`（写得出一句关于对方的话）
4. 从未被任何渠道触达过的优先于已发过邮件的

没有 `hook` 的客户不进队列。一条说不出对方任何事的陌生私信，在社媒上比在邮件里更像
垃圾——邮件至少还有主题行可看，私信只有那一句话。

### R5 每条都是写好的，不是模板占位

队列里存的是**渲染后的正文**，就是要发出去的那段字。Allen 看到什么就发出什么，
不需要在脑子里替换 `{company}`。他改过的正文原样保存，Agent 不再覆盖。

正文过 `message_guard`：价格闸门照旧，个性化闸门照旧（社媒私信全部按首触算）。
被拦下的不进队列，理由记在队列行上，因为那通常说明这家客户的 hook 该补了。

### R6 同一天不许发出两条一字不差的私信

`hook` 是从网站关键词生成的，好几家公司合法地拿到同一句话——写测试的时候第一批
队列里三条私信一模一样，就是这么来的。而一模一样的陌生私信同一个早上批量发出去，
是平台最容易认出的机器人特征，没有之一。

所以正文必须**逐条不同**。撞车的那条不入队，理由写明是哪家公司的 hook 太通用——
那句话就是该去补的东西。

### R7 队列不过夜

昨天的队列今天作废。社媒的时机性比邮件强，而且一份三天前排好的私信队列，
里面的客户状态早就变了。每天重新生成，昨天没发的自然消失，不累积成第二个 89 条待办
（见 [48 号 spec](48-spec-outbound-guards-and-quiet-agent.md) R3）。

## 验证

- `tests/test_social_dm_queue.py`：同一天不会出现两条一字不差的私信；
  每渠道条数落在 8–15 内且不是固定值；Facebook 更少；
  一家公司不会同时出现在两个渠道；今天要发邮件的客户不进队列；没有 hook 的不进；
  被 `message_guard` 拦下的不进且留下理由；周末减半；昨天的队列不会出现在今天。
- 队列本身永远不触发发送：没有任何自动路径读这张表去发消息。
