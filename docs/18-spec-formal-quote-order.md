# Spec 18 — 正式报价与订单闭环

> 状态：Implemented / Verified
> 日期：2026-08-12

## 1. 问题

现有“产品报价”只生成一张产品卡 PNG，不关联客户、商机、金额版本和成交结果。业务员无法回答：

- 哪个客户收到哪一版报价；
- 报价金额、有效期、贸易条款和付款条件是什么；
- 报价是否已发送、接受或失效；
- 接受后订单处于定金、生产、验货还是发货阶段。

## 2. 报价模型

`quotes`

- 编号：`MCV-YYYYMM-0001`，自动递增；
- 关联：公司、商机、联系人；
- 状态：`draft/sent/accepted/rejected/expired`；
- 商务：币种、贸易条款、目的地、有效期、付款条件、交期、质保；
- 金额：小计、运费、折扣、总额；
- 时间：创建、发送、接受、更新时间。

`quote_items`

- 描述、型号、像素间距；
- 宽、高、数量；
- 计价单位 `sqm/unit`；
- 单价、面积、行金额；
- 备注。

面积计价：`宽 × 高 × 数量 × 每平方米单价`；件数计价：`数量 × 单价`。金额始终由后端计算，前端不能直接伪造总额。

## 3. 报价状态与商机联动

- 草稿可编辑明细和商务条件。
- “已发送”要求至少一条有效明细且总额大于 0。
- 标记已发送后，商机自动进入“已报价”，金额同步，并创建 3 天后的“跟进报价”任务。
- “已接受”只允许从已发送状态进入。
- 拒绝/失效保留历史，不删除金额版本。

## 4. 订单模型

`orders`

- 一个已接受报价最多转一个订单；
- 编号 `MCO-YYYYMM-0001`；
- 状态：`confirmed/deposit/production/inspection/shipped/completed/cancelled`；
- 金额：订单总额、定金、已收款、余额（后端计算）；
- 履约：预计发货日、实际发货日、物流单号、备注；
- 转订单后商机标记成交，成交金额等于报价总额。

## 5. 正式文件

- 每张报价提供只读打印页，包含 Maxcolor、客户、联系人、项目、明细、商务条款和总额。
- 打印页由记录实时生成，浏览器可“打印/另存为 PDF”；避免生成后内容和数据库版本不一致。
- 快速产品卡 PNG 保留，用作开发阶段的营销附件，不再冒充正式报价。

## 6. API 与界面

- 报价：列表、详情、新建、编辑、状态变更、打印页、转订单。
- 订单：列表、详情、更新状态/收款/发货信息。
- “产品报价”页面改名“报价订单”，顶部为正式报价与订单工作台，底部保留产品库和快速报价卡。

## 7. 验收

1. 面积/件数计价、折扣、运费和余额计算准确。
2. 非法状态流转、空报价发送、重复转订单被阻止。
3. 报价发送同步商机金额/阶段并生成跟进任务。
4. 转订单同步商机成交且订单状态可推进。
5. 正式打印页字段、HTML 转义和金额一致。
6. 全量测试、前端构建、真实迁移和浏览器冒烟通过。
