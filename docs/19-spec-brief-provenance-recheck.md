# Spec 19 — 客户简介、邮箱来源、官网复检

> 状态：Implemented
> 日期：2026-08-05
> 来源：分析 github.com/trycompai/crm（agentic-first CRM）后确定借鉴的三条

## 1. 业务问题

三个问题都出在同一层——客户数据质量层，也是本系统一直最薄的一层（`enrich.py` 正则一次性抓取、`icp.py` 关键词打分，抓完就不再看）：

1. **消息个性化度不够**。模板只有 `{name}/{contact}/{country}/{city}`，发出去一眼群发味，回复率上不去。
2. **邮箱来源不可追溯**。官网联系页写给买家的地址、页脚扒的地址、自己敲的地址，在库里长得一模一样，但值得的信任完全不同。
3. **触达过没回的客户永久沉底**。跟进序列跑完就结束，474 条里大部分再也不会被看第二眼——而对方官网可能已经换了联系人、上了新项目。

## 2. 设计原则

**只写来源说过的**。简介、开场白全部由官网页面上实际出现的内容拼出：ICP 关键词命中的原词（带引号，让读的人一眼看出这是人家自己写的，不是我们的判断）、页面印的像素间距。不接大模型改写——一句编出来的「贵司在拉美市场领先」客户自己知道不是真的，整条消息从那句起就露馅了，比不写更糟。

**宁可留空，也不重复已知信息**。简介不写公司名、不写 ICP 类别、不写城市——这三样分别是抽屉标题、`target_fit` 列和独立字段。初版写了「`{公司名}` is `{类别}` in `{城市}`」，而公司名取自页面标题，于是在 /contact 页上生成了 `Contact is a signage company`，在一个 404 页上生成了 `Página não encontrada is an event rental company`。重复可见字段本来就不划算，重复错了更糟。只匹配到 ICP 类别、没有任何具体信息时，简介直接写空。

**简介给自己看，开场白给客户看，两者规则不同**。`brief` 是第三人称的阅读材料（`The site mentions "rental"…`），不做发送变量——模板真发出去等于把客户官网原话念给他听。而「不重复记录已有信息」这条**只管简介**：简介旁边就是公司名、分级、城市，客户却从没见过我们的分级，所以在我们屏幕上是废话的东西，在客户那边是开场白。初版把这条规则也套在开场白上，导致只匹配到一个关键词的客户连开场白都没有，这是错的。

**非英文关键词配英文释义，不丢弃**。`icp.py` 按站点语言匹配，韩国招牌厂命中 `전광판`，墨西哥站命中 `publicidad exterior`。初版为了句子好看把非 ASCII 词过滤掉，等于让韩国（主力市场之一）全部空白。改为每个关键词带英文释义：简介引用官网原词并加注释义（`mentions "전광판" (LED signage)`），开场白只用释义（`Saw the LED signage work on your site.`），因为消息本身是英文的。

**两者分开门控，也必须分开存储**。`brief` 和 `hook` 各有各的产出条件（简介要一条规格或两条站点事实，
开场白只要一个可发送的词），所以落库也必须各写各的。初版把 `hook` 写在「有 brief」的分支里，结果
「有开场白没简介」的客户两样都没存下来——正是韩国单关键词站，等于把释义表那个修改整个抵消掉，而且
还给这些客户记上「没内容、别再读」。存量回填第一轮 388 家有简介、388 家有开场白，两个数字完全相等，
就是这个 bug 的信号。

**空值必须能安全消失**。`{hook}` 写成完整句子（自带句号），模板里去掉这一句剩下的话依然通顺；渲染时补一次空格合并，不会发出 `Saw  on your site.`。

**查了没变化就什么都不产生**。复检没发现变化 → 不建任务、不写备注、不加角标，只把下次日期推后。每季度汇报一次「没事发生」的任务列表，人就不看了。

**冲突不自动改**。官网上的值和库里的值不一致时只写进备注，绝不覆盖——网站可能改版了，也可能抓到的是页脚上合作伙伴的地址，用它悄悄换掉一个能用的邮箱是比不查更坏的结果。

## 3. 数据模型

`leads` 新增：

| 列 | 含义 |
|---|---|
| `brief` | 英文客户简介，由官网内容拼出，只给自己看，可手改 |
| `hook` | 一句开场白，模板变量 `{hook}`，只由像素间距生成，可手改 |
| `email_source` | `site.contact-page` / `site.homepage` / `manual` |
| `recheck_due` | 下次复检官网的日期 |
| `recheck_count` | 连续几次复检没有变化（用于退避） |

不新增 `contact_source`：`contacts.source`（legacy/manual/reply/discovered）已经记录了联系人来源。

## 4. 复检节奏

间隔按契合度分档，并随「查了没变化」退避，上限一年：

| 契合度 | 首次间隔 |
|---|---|
| ≥ 85 | 30 天 |
| ≥ 70 | 90 天 |
| 其他 / 未分级 | 180 天 |

- 触发点是**发送**本身（`_mark_messaged`）——没触达过的客户没有「再看一次」的必要。日期只设一次，第二次触达不会让官网变新。
- 每天后台扫一次，上限 20 条（每条都是一次真实网页抓取，和发送同样的克制）。
- 排除：已回复、不再联系、已赢/已丢、没有官网。
- 抓不通的站按正常节奏推后，不每轮重试死域名。

## 5. 变更点

- 新增 `app/brief.py`、`app/recheck.py`
- `app/enrich.py` 返回 `brief` / `hook` / `email_source`
- `app/personalize.py` 支持 `{hook}`（`brief` 刻意不做发送变量），空值不留空档
- `app/backfill_brief.py` 存量分批回填，走 `recheck.run(first_read=True)`
- `app/outreach.py`、`app/channel_outreach.py` 的 `_mark_messaged` 排复检日期
- `app/main.py` 后台循环加 `auto_recheck()`（`OUTREACH_AUTO_RECHECK=0` 可关）
- `POST /api/leads/{no}/recheck` 手动立即复检
- 客户抽屉顶部「客户简介」区块：简介、开场白、邮箱来源、下次复检、复检按钮

## 6. 像素间距的取值规则

`P3` 在互联网上大多数时候是章节号、页码或产品编号。实测三家真实客户官网（ledwave.com.br /
pantallasled.mx / worshipproductions.org）后定的规则：**token 前 40 字符内必须出现 `led` /
`pitch` / `pixel`**。这些站写的是 `painel de LED P3`、`pantalla-led-p8-smd`，全部命中；而
`Chapter P3 of the manual` 这类被挡掉。取值范围限定 0.5–20，去重后按数值升序；≥4 个时写成
区间（`P1–P10`）而不是列前三个——更短也更准。

## 7. 抓哪些页面

联系页优先（`/contact`、`/contact-us`、首页），联系方式齐了就停。**规格印在产品页**，所以联系页
这一轮没抓到任何像素间距时，再试 `/products`、`/productos`、`/produtos`、`/product`，抓到规格
就停。已经有规格的客户不会多抓，每一次都是真实网络请求。

公司名只认首页标题：联系页先抓，标题是「Contact」「Inicio」「Página não encontrada」，8 家实测
5 家中招——快速添加粘贴官网时公司名就会变成这些。同时加了一份通用页名黑名单（中英西葡韩），
命中就返回 None，让调用方回退到域名推断的名字。

## 8. 存量回填

`python -m app.backfill_brief [--limit N] [--delay 秒] [--all]`

书里几百家公司都是这套东西存在之前收的，每家都要真实抓一次官网——这是几小时的网络请求，不是
迁移脚本，所以做成分批、可续跑的命令而不是启动时自动跑。默认取 40 家最早的、还没写过简介的，
再跑一次自动接着上次的位置。写入走 `recheck.run(first_read=True)`，所以「空的才填、冲突只记备注、绝不覆盖」的
规则自动适用。抓完确实没内容的站会记 `recheck_count`，下一批不会反复重试同一批哑站。

**首次读取不建任务**。回填读到的东西按定义全是新的，715 家全都报一次「官网有更新，可以再触达」
等于用几百条非事件把真正有变化的那几条埋掉。发现照样写进该客户自己的备注时间线（前缀「首次读取
官网：」而不是「官网复检：」），那里是来源记录，不是待办。只有后续真正的复检才建任务。

## 9. 已知边界

- 官网只写「联系我们」不写业务内容的公司，简介仍然是空的——这是设计结果，不是缺陷。
- 覆盖面取决于 `icp.py` 的关键词表和 `brief.py` 的释义表，扩关键词要同时补释义，否则新词进不了
  开场白。
- 复检只读官网，不读社媒。IG/FB 主页的更新不在这条链路里。
