＃ 73 — 「已联系」是有保质期的

## 问题不是限额，是池子被历史记录锁死了

Allen 要每天 50 封以上。今天有邮箱的线索 1006 家，其中 881 家被标成 `messaged`，
「没发过」的只剩 **8 家**。看上去池子见底了，但把最后一次联系的日期拉出来是这样：

| 上次联系 | 家数 |
|---|---|
| 7 天内 | 131 |
| 30 天内 | 100 |
| 半年内 | 321 |
| **一年以上** | **329** |

这 329 家大多是小满 CRM 导进来的历史记录，最久的 1421 天前——将近四年。
`outreach.eligible_leads` 里写的是 `status IN ('messaged','replied')` 就永久排除，
**没有时间衰减**。于是 2022 年发过一封没回音的公司，2026 年仍然被系统判定为「已联系」。

一个四年没说过话的公司不是老客户，是一条全新的线索。

## R1 单纯发过没回音的，180 天后重新可发

冷却期只对**一种**状态生效，其余全部维持永久排除：

| 情况 | 判定 |
|---|---|
| `status='replied'` 回复过 | **永久排除**——这是关系，不是线索 |
| `stage='won'` 已成交 | **永久排除**（[54 号 R1](54-spec-import-existing-customers.md)：付过钱的人不能收到开发信） |
| `stage='lost'` 已判死 | **永久排除**——Allen 判过的客户不该被日历复活 |
| `do_not_contact=1` | **永久排除** |
| `email_status='invalid'` | **永久排除**——36 家退信的地址全部已经在这里，冷却期不会把死地址捞回来 |
| `status='messaged'` 且超过 180 天 | **重新可发** |
| `status='messaged'` 但没有发送日期 | **不放行**——不知道什么时候发的就不赌 |

已成交那条必须单独写出来，因为它真的会出事：按 180 天算，现在就有 1 家 `won`
会被捞回冷邮件池。发一封「我们是深圳做 LED 屏的」给已经打过款的客户，
是这套系统最丢人的失败方式。

**180 天不是行业惯例抄来的**，是这批数据的实际形状：30 天内联系过的 100 家不该碰，
半年内的 321 家还在跟进序列里走，真正躺着不动的就是一年以上那 329 家。
180 天这条线把它们放出来，同时不碰任何还在进行中的对话。

## R2 只改「能不能发」，不改「有没有联系过」

冷却期只作用于发送资格：`outreach.eligible_leads`、`channel_outreach` 的渠道资格、
社媒队列的筛选。

**仪表盘和 health 的统计口径一个字不改。** `touched`、`funnel`、`reach` 回答的是
「我们和多少家公司说过话」，那是历史事实，不会因为过了半年就变成没说过。
把统计也接上冷却期，等于让报表为了好看而撒谎——[45 号](45-spec-truthful-lead-facts.md)
那条规矩管的就是这个。

## R3 到期跟进不够额度时，从可重发池补位

只改资格是**看不到任何效果的**：`autosend` 每天只发到期的序列步骤，
它根本不看 `eligible_leads`。资格放开而没人入组，池子里那 329 家会继续躺着。

所以补位：当天到期的跟进少于当天剩余额度时，从可重发池里按顺序入组，补到额度为止。

- 补位走现有的 `sequences.enroll_leads`，语言过滤、查重、回复排除全部沿用，不新开路径
- 一天最多补到当天剩余额度为止，**不预支明天**
- `UNIQUE(lead_no, sequence_id)` 天然挡住重复入组：一家公司走完过角度二，
  就不会被再次放进角度二收同样的三封信

## R4 退信照旧「换人发」，不是「换个日子再发同一个地址」

Allen 的规则是退信率高就要多发、换话术、找别的负责人，不能因为退信就少发。
这条 spec 不动它，也不能被误读成对它的实现——**冷却期不会重发任何退信过的地址**，
那 36 家的 `email_status` 已经是 `invalid`。找这家公司的另一个联系人，
是[退信任务](70-spec-discovery-sources.md)那条路的事。

## 这条 spec 能解锁多少（实测，不是估算）

冷却期放出 **321 家**。但「过了冷却期」不等于「写得出信」，把这 321 家拆开看：

| | 家数 | |
|---|---|---|
| 有公司名也有个性化线索 | **200** | 立刻可发 —— SNA Displays、Vantage LED、Trans-Lux 这类真公司 |
| 有真公司名，缺 hook/官网/城市 | 77 | 质量闸会拦，得先补信息 |
| 「公司名」是一个邮箱地址 | 44 | 小满导入的脏数据，写不出称呼 |

补位入组只取那 200 家。后两类不入组——不是因为它们不重要，而是因为
[质量闸](49-spec-rendered-message-guard.md)在发送时本来就会拒绝它们，硬塞进去不会多发一封信，
只会让它们停在 `quality_hold` 里，把当天的额度白白吃掉。
seed_angle2 要去救的那 110 封停摆跟进，就是这么来的。

200 家按每天 48 封算，**约 4 天的发送量**——这是一次性补充，不是可持续来源。

写清楚这一点是为了不自欺：真正每天 50 封的可持续来源只有开发新客户
（[68 号](68-spec-develop-not-just-send.md)、[71 号](71-spec-social-watching.md)），
冷却期买到的是四天时间，不是一个答案。那 44 条把邮箱当公司名的脏记录，
是小满导入时 `_placeholder_name` 没拦住的，该单独修。
