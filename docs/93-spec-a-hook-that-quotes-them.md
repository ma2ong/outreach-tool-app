＃ 93 — 开场白要么引用他们自己的话，要么说通用的那句

## 从落位测试来的

2026-09-03，918 封邮件、503 家公司、4 家回过（其中 1 家是拒绝）。回复率 0.8%。

先查了通道，因为「信没被看见」和「信写得不对」的修法是相反的：

* mail-tester 9/10，发件 IP `160.236.52.5` 不在任何黑名单，SpamAssassin 通过，
  内容干净（纯文本、无图、无短链），SPF/DMARC 通过；
* 英文和韩文首封发到真实 Gmail 和 Outlook，**两家都落在主收件箱**，不是推广栏。

**通道结案。0.8% 是信本身的账。** 于是量了 354 封首封的第一句话：

| 开场白 | 数量 |
|---|---|
| 说了这家公司**自己的**具体东西 | **3 封** |
| 按类目泛泛说（「看到你们做租赁/标牌」） | 239 封（67%）|
| 完全没提对方（「我们在深圳做屏」） | 52 封（14%）|
| 其余 | 在讲我们自己的规格 |

收信的人一天收五封深圳来的信。「看到你们做租赁」这句话对韩国那 300 家里的任何一家
都成立——他不是没看见这封信，他看见了，然后认出这是那一类信。

## 这是两条既有规矩的账单，两条都还是对的

`brief.py` 开头写着：不推断、不改写，因为「一句自信的编造（"拉美市场的领导者"）进了
冷邮件，客户知道那不是真的，整封信从那句起就像机器写的」。**这条今天依然成立。**

docs/80 R2 写着：没有开场白不是不写的理由。docs/85 给了每个人一句通用开场白，
`message_guard` 因此放行 `GENERIC_HOOK`。**这条也依然成立**——Allen 的原话是
「引不出就用通用的」。

两条合起来的结果就是那个 67%：正则只认得出类目，于是所有人都拿到类目级的开场白。

**缺的不是「让模型自由发挥」，是一个中间档：模型可以写，但必须把话的出处交出来。**
这正是 docs/45 的规矩（写不出出处的不写），只是从未用在 hook 上。

## docs/91 已经走到这堵墙前面，这份规格是接着它写的

09-02 的 docs/91 修的是同一件事的上游：社媒访问只记类别不记原话，628 家排队而每天
重读同两家。它的 R3 明确写了「记那句话，不记那个类别」，并且把社媒原句接进了 hook。

**但它在最后一步被同一堵墙挡住了**，规格里自己写着：

> hook 的替换要守 docs/85 的两条既有约束：词汇必须是 `personalize._HOOK_GLOSS_KO`
> 认识的，句式必须是 `hook_ko` 能匹配的，否则韩语开场白会整句消失。

于是 `hook_from_signals` 实际落地成了「社媒信号类别 → 词表里的一个词」，产出仍然是
类目级的开场白，只是换了个来源。**它拿到了原话，却只能把原话丢掉、交出类别。**

这份规格拆的就是那堵墙（R3）。docs/91 的取材、去平台框架、日期判定全部保留并复用
——它已经把「可引用的原句」这个原料备好了，缺的是一个能把原句原样送出去的管道。

## R1：模型必须交回一句原文，且逐字对得上，否则整条作废

模型返回三样东西：开场白、它依据的**原文片段**、那句话来自哪个 URL。

**校验是机械的，不是承诺**：原文片段必须是抓到的页面正文的逐字子串
（归一化空白后比对）。对不上就丢弃整条，走 R2 的下一级。

模型「说它引用了」不算数——今天上午的 docs/78 就是被一张 Cloudflare 反爬页骗成
85 分集成商的。子串比对是这条规格里唯一不能省的一行。

## R2：三级兜底，永远不因为没有开场白而不发

```
模型写的（原文校验通过）
  ↓ 引不出
brief.py 的正则开场白（今天的行为）
  ↓ 也没有
GENERIC_HOOK（docs/85）
```

Allen 的决定：引不出就用通用的。**这一级链条上任何一环失败，都不能变成「今天少发
一封信」**——docs/80 R2 的理由没有变。

## R3：韩语开场白由模型直接用韩语写，不再过词表

这条是这份规格里最容易被漏掉、漏掉就当场坏掉的一条。

`personalize.hook_ko` 今天的做法是：把存下来的**英文** hook 用两条正则匹配成固定句型，
再把术语逐个查 `_HOOK_GLOSS_KO` 词表翻成韩语。**匹配不上就返回空字符串**，韩语信
就没有开场白了。

一句模型自由写的英文 hook，两条正则一条都匹配不上。**韩国是最近发信量最大的市场
（8-27 之后 200 多封）——不处理这条，改完的结果是韩语信全部丢掉开场白。**

做法：韩国客户的官网本来就是韩语的，让模型**直接引韩语原文、直接写韩语开场白**。
这比今天的「英文正则 → 词表回译」更贴原文。`leads` 增加 `hook_ko` 列，
`personalize.hook_ko` 优先读它，读不到才退回现有的词表通道。

## R4：开场白是一件事实，不是一个形容词

约束写进提示词，并在代码里检查：

* 只能说他们做过/有的一件具体东西：一个项目、一个场馆、一条产品线、一个规格；
* **禁止评价性措辞**（leading / professional / impressive / 훌륭한 …）——一句夸奖
  既没有出处，也正好是「机器写的」那个味道；
* 不出现我们的产品、我们的规格、任何价格；
* 一句话，不超过 20 个词（韩语 40 字），因为它后面紧跟着自我介绍。

## R5：出处随行

`leads` 增加 `hook_quote`、`hook_source_url`、`hook_at`。docs/45 要的是出处，
这里的出处是客户官网上的一句话，可以点开核对。

`refresh_hooks` / `backfill_hooks` 不得覆盖带出处的 hook——它们是从书里已有材料
重写塌陷的通用句，出处更强的那句不该被它们碰。

## R6：不为这件事重跑 1311 家

页面正文今天不留存（`enrich` 抓完即弃），所以给存量客户补 hook 等于重抓一遍官网。

不做一次性大重跑：**跟着 `recheck` 走**。官网重读本来就在排期里，重读时正文在手，
顺路生成 hook，边际成本只有一次模型调用。要 Allen 手动催某一批时再单独跑。

## R7：模型写的开场白仍要过 `message_guard`

渲染后的整封信照旧过守卫（docs/49）。被拦下就退到 R2 的下一级，不放宽守卫。

## 验收

1. 模型给的原文片段不在页面正文里 → 这条 hook 不落库，`leads.hook` 保持原值。
2. 模型返回一句带 "leading" 的开场白 → 被拒，退到下一级。
3. 韩国客户：`leads.hook_ko` 有值时，渲染出的韩语首封用的是它，不是词表回译的句子。
4. 模型不可用 / 超时 / 返回坏 JSON → 首封照常发出，用正则或通用开场白，
   **发信量不因此下降一封**。
5. 带 `hook_quote` 的 lead 跑一次 `refresh_hooks --apply`，hook 不被改写。
6. 生成的 hook 落库时同时写入 `hook_quote` 和 `hook_source_url`。

## 没做的

* **不让模型写 `brief`。** brief 的读者是 Allen，正则够用，而 `brief.py` 开头那段
  拒绝推断的理由没有过期。这份规格只动 hook——**客户看得见的那一句，恰恰是出处
  要求最严的那一句**，所以给它模型的同时给它子串校验。
* **不让模型改写正文的其他部分。** 产品段落是从产品库来的（09-03 刚对齐过），
  它的真值在 `products` 表里，不在模型脑子里。
* **不为此建离线评测集。** 提过，Allen 否了。这份规格的验收靠上面 6 条断言。
