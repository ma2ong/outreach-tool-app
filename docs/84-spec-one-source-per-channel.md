## 病根不是「条数多」，是「同一件事有三份文案」

「给一个没写过的公司写第一封信」这件事，现在有三个地方各写了一份：

1. 序列的开场白 —— 自动发送走这条
2. `templates` 表的「首次触达」 —— 手动面板走这条
3. Agent 的 `send_outreach` 挑一个 `template_id` —— 1094 次提议里用过 1 次

三份就必然有两份过期。事实正是如此：#2 停在几版之前，一封都没发过。
[docs/82](82-spec-never-offer-to-go-away.md) 的六条规则改的是 #1，#2 一个字没跟上。

## R1：一个渠道一份文案，其他地方只能引用

* **冷邮件** → 序列是唯一来源。手动面板里的「冷邮件」模板由中性版序列**生成**，
  不再手写第二份。改序列就改了模板，走不岔。
* **社媒私信** → `social_queue` 是唯一来源。模板表里的私信模板由它生成。
* **资料邮件**（产品线对比 / 规格书）→ 这是真正不同的一类：不是冷开场，是主动发一份东西。
  留在模板表里手写，因为没有别的地方在写它。

## R2：有 hook 的客户不该拿到更泛的文案

`_compose` 分两套：有 hook 走 `_TEMPLATES`（4 条，**不分客户类型**），
没 hook 走 `_GENERIC`（按客户类型分）。结果是反的 —— **467 家信息更全的客户，
收到的是不分类型的话；161 家什么都不知道的，反而收到按类型写的。**

合成一套：问候 + hook（有就加）+ 按客户类型的那句。hook 从模板内部挪到句子前面，
它就不再影响后半句能不能成立 —— 那正是当初要分两套的原因。

## R3：一套命名

三套命名同时存在，是「乱」最直接的来源：

```
冷邮件 3 步跟进（英语·活动租赁）     ← 序列
首次触达（英语）                    ← 模板
DM 首次触达（英语） · IG            ← 模板
```

统一成 `类别 · 细分（语言）`：

```
冷邮件 · 中性版 · 第1封（英语）
私信 · 活动租赁（英语）
资料 · 产品线对比（英语）
```

序列名不动 —— 它已经是这个形状，而且 `seed()` 按名字匹配，改名会孤立掉每一个报名
（[docs/83](83-spec-a-number-we-cannot-dial-is-not-a-number.md) 之前刚踩过一次）。
