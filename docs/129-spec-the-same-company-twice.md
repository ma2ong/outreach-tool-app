# 129 — 同一家公司在库里出现了两次

## 表格入库之后，Allen 数出一堆重复

《客户资料表》（docs/118）第一次导入时按邮箱 → 官网 → 公司名匹配，匹配不上就新建。
表里写 `(주)에스엔테크`、库里是 `에스엔테크`，官网一边空着，邮箱一边是 naver 一边是公司域——
三条都对不上，于是同一家公司有了第二条记录。09-11 数了一遍：78 条多出来的。

[dedupe.py](../backend/app/dedupe.py) 早就有合并器（补空白、并联系人、挪往来记录、不丢回复），
缺的是**认得出这些是同一家**。

## R1 四种证据里有一种，就是同一家

| 证据 | 例 |
|---|---|
| 任一联系人邮箱相同 | `snp@shownprove.com` 同时挂在 157 和 1099 名下 |
| 官网主域相同（不含博客/社交这类公用主机），且国家相同 | `eng.galaxialed.com` |
| 公司名归一化后相同（去掉 (주)/주식会社/Co.,Ltd/Inc 和标点），且国家相同 | `에스엔테크` = `(주)에스엔테크` |
| Instagram / Facebook 账号相同（`people`、`pg`、`profile.php` 这类不是账号） | `pantallasled.mty` |
| 电话相同，且其中一条只有电话没有官网 | `RDL LED`（只有电话）= `Reddotlogics` |

国家为空的记录和任何国家都能配；公司名相同但一边国家为空的不算（Trans-Lux 美国 / Translux 英国）。

**两条都有官网、只有电话相同不算**：同一个老板可以有两个牌子（ATH Productions / Bounce Multimedia），
合并了就把两个网站、两套联系人揉成一条。同名但不同国家也不算（LATINLED 巴西 / 阿根廷，
LED Solutions 加拿大 / 芬兰）；同一主域但不同国家的是加盟店（FunFlicks 加拿大 / 肯塔基）。
这三类列出来给 Allen 决定，不自动合。

## R2 留编号小的那条，表格说的照样算数

编号小的是老记录，往来、备注、任务都挂在它下面。合并只补空白、并联系人、挪记录。
合并完**重跑一次表格导入**：表里那一行现在匹配得到保留下来的记录，docs/118 R4「表格为准」
自然生效——不用在合并器里再抄一份规则。

## R3 「不联系」跟着走

两条里有一条是 `do_not_contact=1`，合并后必须还是 1。原来的合并器只补空白字段，
0 不是空白，于是一家成交客户合并后会重新进开发队列。`no_cold_outreach` 同理。
