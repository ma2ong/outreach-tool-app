## 1. 结论

工具本身的销售闭环在 Doc 21 已经贯通。这一轮加的是**决策层**：

`回复进来 → 判意图 → 该我做的起草、该你做的汇报 → 每天早上出计划 → 你审批 → 从你的决定里学`

三期都已落地并在真实数据上跑过。**当前系统的瓶颈不在功能，在转化**——见第 4 节，那不是这轮能修的。

|---|---|---|---|
| A | 意图分类、回复起草、客户记忆 | 已上线 | 分类脱敏后出网；草稿出现未溯源的价格/交期自动升 high risk |

**贯穿三期的硬边界**：报价永远由 Allen 做（Spec 22 §4.6）。`quote` / `negotiation`
两类意图永不起草，代码兜底剔除，配置也加不回去。

## 3. 审批脊柱是这轮的地基

所有能力挂在同一条 `agent_proposals` 上，因此：

- **自主度是逐格旋钮**（八类动作 × off/propose/auto），不是一个总闸；
- **执行器只调既有模块**，所以单批 20、日限 40、同客户每日一次、无效邮箱跳过、
  `do_not_contact` 全渠道排除，对 Agent 发起的动作**自动生效且无处可绕**；
- `auto` 档也照写执行记录——跳过的是"问"，不是"记"。

> 2026-08-20 的真实教训：八个旋钮一度全被设成 `auto`。没有造成损失（当天 0 条发出），
> 但这说明**旋钮状态本身需要被看见**。已把碰客户的四类调回 `propose`。
> 后续若做多人使用，自主度变更应当进审计日志。

## 5. 本轮修掉的真实缺陷

1. **改稿 diff 一直在被销毁**：`approve()` 用改后内容覆盖原稿，而注释还写着
   "这个 diff 是 C 期最好的数据"。已加 `original_payload`。
2. **回信从轮换邮箱随机发出**：客户写给 A 箱、我们从 B 箱回，线程断且像另一家公司。
   已加 `inbox_messages.mailbox_email`，从客户当初写信的地址回。
3. **自动跟进静默死了两周**：`run_once` 先标记当天已跑、再读到期队列，读队列抛错被
   调度线程吞掉；结果行停在 08-05，就绪中心一直显示绿勾。已把读队列移进 try，
   并让就绪中心比对结果行日期与运行日期——"已启用"不等于"在工作"。
4. **9 条客户的公司名是网页标题**（`Contact` / `Page not found`）。它们是有官网有联系人的
   真公司，所以改名不删除；官网标题是广告语时退回用域名。
5. **`_migrate_columns` 在新库上会 ALTER 一张还不存在的表**（由模块自己 ensure_schema 建的）。

## 7. 下一轮的优先级

按投入产出排序，前两条与 Doc 21 的判断一致，只是更紧迫了：

1. **换发信身份**（P0）：启用 `mcvisualled.com` 发信。Zoho 免费版 SMTP 可用但 IMAP 被锁，
   只加它当发件箱会让退信和回复收不到——需要评估 Mail Lite 或其他邮箱服务。
2. **补可联系池**（P0）：273 个未触达客户里只有 40 个有邮箱。深挖抓不到的站点是产品天花板，
   但名录/竞品经销商页这条路还没跑满。
3. **让 Agent 攒够学习样本**（P1）：需要 Allen 真实改稿 5 次，无法加速。
4. **回复/商机样本太少，暂不做深层归因**（P2，与 Doc 21 同判断）。0 商机 0 报价的情况下，
   任何按客户类型/职位的转化率细分都会输出误导性百分比。
