＃ 97 — 开场白也可以来自他们上个月发的帖

## Allen 的话（09-03）

> 开场白引用官网原文 **或者看到社媒最近做的一些项目**，然后引不出退回通用句。

## 为什么社媒这一路值得单接

docs/93 让模型从官网正文里引一句原话写开场白。官网有个毛病：**它是三年前写的**。
docs/91 已经把社媒访问改成「记那句可以引用的话，带日期、带出处、去掉平台框架」，
而一条上个月的帖子讲的是他们上个月做的项目 —— 比官网上挂了三年的公司介绍具体得多。

材料早就备好了，缺的是把它交给 docs/93 那条管道。

## R1：社媒文字走和官网正文同一条校验

`hook_writer.improve` 不区分材料来自哪里：模型写一句开场白，交回它依据的原文片段，
片段必须是**这次读到的主页文字**的逐字子串，对不上就整条作废。

清理过的主页文字（`strip_chrome`，docs/91 R4）才进模型 —— 一句混着「服务条款 ·
Cookie」的引文，永远不能放进给客户的信里。

## R2：已经有出处的开场白不被社媒盖掉

docs/91 R3 立过一条不降级规矩：拿一个类别词换掉官网建出来的开场白是降级。
那条规矩还成立，判据换成出处：

* `hook_quote` 有值（官网原话）→ 社媒不动它；
* 没有出处（正则句、通用句）→ 让模型用社媒材料写。

两条都引得出时谁更好，今天没有证据回答，所以按「先到先得、不互相覆盖」处理，
而不是发明一个优先级。

## R3：引不出仍然退回通用句

三级不变：模型（原文校验通过）→ docs/91 的类目句 → docs/85 的通用句。
一封信都不会因为没有开场白而少发。

## 顺带修的：测试真的打了线上模型

接上这条通道之后，`test_social_watch_learns.py` 的两个测试**真的调用了 DeepSeek**
——`backend/deepseek_key.txt` 就在仓库里，`complete_json` 找得到它。

AGENTS.md 写着测试永不调用真实模型，但没有任何东西在执行这一条。现在
`conftest` 有一条 autouse fixture，把 `_call_cli` / `_call_deepseek` / `_call_api`
三个真正发请求的函数换成拒绝。

挡在传输层而不是 `_call_backend`，是因为后端降级本身有测试，它们替换的正是这三个
函数，替换发生在 fixture 之后，覆盖得掉。

## 验收

1. 一条社媒原句能引出开场白时，`leads.hook_quote` 和 `hook_source_url` 写的是这条帖子。
2. `hook_quote` 已有值的客户，社媒访问不改它的开场白。
3. 模型不可用时，社媒访问的行为和 docs/91 完全一样。
4. 整个测试套件跑完，`_call_deepseek` 一次都没有被真的调用。
