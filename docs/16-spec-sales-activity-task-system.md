# Spec 16 — 销售活动与任务闭环

> 状态：Implemented / Verified
> 日期：2026-08-04
> 需求完整度：96/100（角色、问题、主数据、触发规则、优先级和验收标准已明确）

## 1. 要解决的问题

当前系统已有客户、收件箱、跟进日期和商机，但“下一步该做什么”分散在三个位置：

- 客户表的 `follow_up_date` / `next_action`；
- 收件箱中的待处理回复；
- 商机的 `next_action_date` / `next_action`。

这会让业务员重复录入，且无法回答最重要的日常问题：**今天先跟谁、做什么、是否已经做完。**

本批次建立唯一的销售行动主数据 `activities`。客户和商机原字段暂时保留兼容，但由活动系统同步，避免一次性破坏既有筛选、导出和报表。

## 2. 核心用户流程

### 每日工作台

1. 打开“销售任务”，先看逾期，再看今日，最后看未来安排。
2. 点击任务进入客户详情，完成电话、邮件、WhatsApp、会议、报价等行动。
3. 完成任务后勾选“已完成”；若仍需跟进，立即创建下一项任务。

### 客户回复

1. 系统首次识别到真人回复时，自动创建高优先级回复任务。
2. 自动回复、退信和纯附件不创建真人回复任务。
3. 在收件箱点“已处理”时，关联任务同步完成，避免两处重复操作。
4. 同一封回复重复拉取时不得重复建任务。

### 商机推进

1. 商机填写“下一步动作 + 日期”后，自动生成或更新一条关联任务。
2. 商机进入成交或丢单，或清空下一步动作时，未完成关联任务自动取消。
3. 任务与商机必须关联同一个客户，防止数据串线。

## 3. 数据模型

`activities`

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `lead_no` | 所属客户，必填 |
| `opportunity_id` | 所属商机，可选 |
| `type` | `task/call/email/whatsapp/instagram/meeting/quote` |
| `title` | 明确、可执行的动作 |
| `due_at` | `YYYY-MM-DD`，可为空 |
| `priority` | `high/normal/low` |
| `status` | `open/done/cancelled` |
| `source` | `manual/reply/opportunity/legacy` |
| `source_ref` | 自动任务幂等键，如 `inbox:123`、`opportunity:8` |
| `note` | 行动补充信息 |
| `created_at` | 创建时间 |
| `completed_at` | 完成时间 |
| `updated_at` | 更新时间 |

关键约束：

- 自动任务使用 `(source, source_ref)` 唯一索引，防止重复。
- `opportunity_id` 存在时，商机必须属于 `lead_no`。
- 状态、类型、优先级必须在允许值内。

## 4. 兼容和迁移

- 启动时，把已有客户 `next_action` / `follow_up_date` 迁为一条 `legacy` 活动；迁移可重复执行且不会重复。
- 启动时，为尚未处理的真人回复补建回复任务。
- 每次活动创建、修改、完成或取消后，把该客户最早的未完成任务同步回 `leads.next_action` 和 `leads.follow_up_date`。
- 客户删除时级联删除活动；客户合并时活动改挂到保留客户。

## 5. API

- `GET /api/activities`：按状态、范围、客户、商机过滤；范围支持 `overdue/today/upcoming/no_due`。
- `GET /api/activities/stats`：返回逾期、今日、未来、无日期、全部未完成数量。
- `POST /api/activities`：新建活动。
- `PATCH /api/activities/{id}`：修改活动或状态。
- `POST /api/activities/{id}/complete`：快捷完成。

所有写操作返回最新活动；不存在返回 404，校验错误返回 400。

## 6. 界面

- 侧边栏增加“销售任务”，徽标显示“逾期 + 今日”。
- 页面顶部展示逾期、今日、未来、无日期四个数字，默认显示全部未完成任务并按优先级、日期排序。
- 支持范围筛选、快速完成、打开客户、新建任务。
- 客户详情增加活动区：查看未完成/最近完成任务、创建下一步、快速完成。
- 仪表盘增加任务入口，优先提醒逾期和今日行动。

## 7. 明确不做

- 不做多人分配、权限和销售主管审批；当前是单用户系统。
- 不做复杂日历拖拽、周期任务和外部 Calendar 同步。
- 不用活动表替代沟通历史；`notes` 仍是事实记录，`activities` 是未来行动。
- 不立即删除客户和商机上的兼容字段，避免破坏已有页面和导出。

## 8. 验收标准

1. 手工任务 CRUD、日期范围和统计测试通过。
2. 真人邮件和社交回复只建一次高优先级任务；自动回复、退信、附件不建。
3. 收件箱“已处理”同步完成回复任务。
4. 商机下一步自动创建、更新、取消活动。
5. 活动变更正确同步客户兼容字段。
6. 旧数据库升级、历史下一步和待处理回复回填可重复执行。
7. 后端全量测试、前端 production build、真实数据库迁移与浏览器关键流程全部通过。
