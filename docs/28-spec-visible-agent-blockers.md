# Spec 28 — 让 Agent 的"没反应"变成一句人话

**Status:** implemented and verified
**Date:** 2026-08-20
**Depends on:** Specs 24–26

## 问题

2026-08-20 现场排查：Allen 连点「立刻跑一次」和「出今日计划」，界面毫无变化。
后台记录显示三次运行全部 `success`，计划那次真的调用了模型并花了 45 秒。
Agent 一直在干活，产出却在三个地方无声消失：

1. **计划产出被指纹去重静默吞掉。** `build_plan` 给当天所有提议用同一个
   `dedupe_key = f"plan-{today}"`，而指纹 = f(kind, lead_no, dedupe_key)。找客提议
   没有 lead_no，于是今天每一次计划算出的指纹都是同一个 `e4751d8ba9d1`——它在
   02:37 就被当天第一条提议用掉了。此后当天 4 次计划的找客产出全部命中重复。
   `proposals.create()` 返回 `None` 时既不计入 `proposed` 也不计入 `rejected`，
   界面上因此一个字都不会变。

2. **"没有候选通过自动质量门"是错的。** 当天 15:36 的找客实际搜到 19 个候选、
   18 个可用、14 个匹配分 ≥75，全是美国 LED 租赁/AV 集成商。它们没入库不是质量
   问题，而是那次执行走的是手动勾选分支（`execution_mode != "auto"`），payload 里
   根本没有 `auto_import` 字段。`daily_outcome` 把"字段不存在"当成了"导入 0 家"，
   套用了质量不达标的文案，把 14 家现成客户说成了零。

3. **安全暂停只报故障，不给出路。** 界面只说"已安全暂停邮件自动跟进"，不说退信率
   11.4%、不说是哪 264 封发送里的 30 封退信、也不给恢复入口。Allen 无法判断该修
   什么，更无法在修完后恢复。

三件事的共同点：系统知道发生了什么，但没有一条路把它说给人听。

## 规则

### R1 计划提议按"要做的事"去重，不按"动作类型"去重

同一天对同一件事重复提议是噪音；同一天做两件不同的事被合并成一条是丢工作。

- 找客提议的去重键必须包含目标国家：`plan-{today}-discover-{country}`，与
  `build_mission_fallback` 的 `mission-{today}-{country}` 语义一致——一天一个市场
  跑一轮找客。
- 其余动作维持原键。它们都带 lead_no，lead_no 已经进了指纹，"每天每客户每类动作
  一条"本来就是正确的约束。

### R2 被去重的提议必须被数出来、说出来

`build_plan` 返回值新增 `duplicates`：一个字符串列表，记录哪些提议因与今天已有的
重复而跳过。计划结果文案必须体现它。

理由：`proposed: 0` 有两种完全不同的含义——"模型什么都没想出来"和"想出来的今天
都做过了"。前者要重试，后者要去「已执行」标签看结果。把它们显示成同一片空白，
就是逼人去猜。

### R3 候选在等人导入，不叫质量不达标

`daily_outcome` 必须区分两种 `imported == 0`：

- 那轮找客走了自动导入且确实一个都没过质量门 → `no_qualified_imports`，文案维持
  "今天的找客结果没有候选通过自动质量门"。
- 那轮找客没有 `auto_import` 字段（走手动分支），但 payload 里有可用候选 →
  `candidates_awaiting_import`，文案必须报出候选数量并指向导入动作。

阻塞信息的价值在于指出下一步。把"14 家现成客户等你点导入"说成"没有合格候选"，
不只是文案不准，是把一个 30 秒能完成的动作藏成了一个查不到的故障。

### R4 安全暂停必须同时给出原因和出路

`run.status()` 返回 `safety_pause`（`autosend.safety_pause` 的原文，含 code、
reason、evidence、paused_at）。

Agent 面板在暂停存在时显示：暂停原因、退信证据、以及一个明确确认风险后才生效的
恢复按钮（复用既有的 `PATCH /api/autosend` + `acknowledge_safety_risk`）。

暂停本身是对的，不改判定阈值——11.4% 硬退信继续发会烧掉发件域名。要改的只是
它的表达方式。

## 不做什么

- 不放宽送达率安全闸的阈值。
- 不让找客结果自动入库来"解决"问题 2：手动勾选是 Spec 24 定的确认关口，
  错的是文案不是关口。
- 不动 `execution_mode` 的判定逻辑。当天那批提议由旧代码创建，新的自动导入路径
  在 16:46 重启后才生效，此后因规则 R1 的缺陷再没产生过新提议——修好 R1 后
  这条路自己就通了。
