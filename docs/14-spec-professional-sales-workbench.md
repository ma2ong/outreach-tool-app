# Doc 14 — 专业 LED 外贸销售工作台（Wave O → S）

**状态：** Implemented / Audited（核心范围，后续边界见 Doc 21）
**日期：** 2026-07-30  
**目标用户：** LED display 外贸销售、销售主管、外贸团队负责人  
**需求完整度：** 96 / 100

## 1. 产品目标

把当前“客户搜索 + 多渠道触达工具”升级为销售人员每天可依赖的工作台。系统不仅要能找到客户、发消息，还必须保证：

1. 销售知道系统是否已准备好，异常不会被静默隐藏。
2. 客户回复能及时进入系统并停止后续追发。
3. 自动化默认安全，任何自动发送都可预览、可关闭、可追溯。
4. 客户、联系人、任务、商机、报价和订单形成一条连续业务链。
5. 评分与报表能指导销售下一步行动，而不是只展示数据。
6. LED 行业信号能转化为有理由、有时机的开发动作。

## 2. 当前业务证据

基于 2026-07-30 本地真实数据快照：

- 922 家客户，610 家已触达，312 家仍为新客户。
- 316 个活跃邮件序列全部逾期，最晚应执行日期早于当前日期。
- 系统内客户回复为 0，但已有 3 封退信记录。
- 联系人姓名覆盖 73 家，职位覆盖 28 家，ICP 类型覆盖 219 家。
- 下一步行动、商机和订单数据尚未形成稳定使用习惯。
- 当前没有已配置的轮换邮箱；回复同步只读取单个备用 Gmail。

这些数据说明瓶颈已经从“缺少功能”转为“执行链不可靠、用户无法判断系统状态、业务对象未贯通”。

## 3. 产品原则

- **动作优先：** 首页先回答“今天该做什么”，再展示统计。
- **系统承担复杂性：** 自动推断、自动检查、自动提示，减少销售手工维护。
- **安全默认值：** 自动发送默认关闭；未通过前置检查时不得启用。
- **单一事实来源：** 客户、联系人、任务、商机、报价和订单之间使用稳定关联。
- **错误可行动：** 错误提示必须说明影响和下一步，而不是静默失败。
- **结果可验证：** 每个自动动作都记录时间、范围、结果和失败原因。

## 4. Wave O — 可靠性与每日就绪中心

### 要解决的问题

当前销售无法快速确认邮箱、回复同步、逾期序列和自动发送是否正常；接口字段不完整会让联系人数据在保存后“消失”；回复拉取没有覆盖已配置的多个邮箱。

### 功能范围

1. **联系人字段正确性**
   - 客户详情接口完整返回并允许更新 `contact_name`、`title`。
   - 前端编辑联系人姓名与职位后，刷新仍保持一致。

2. **多邮箱回复同步**
   - 每个发送邮箱可配置 SMTP 与 IMAP。
   - 拉取回复时遍历所有启用邮箱；未配置邮箱时使用备用 Gmail。
   - 单个邮箱失败不阻断其他邮箱，结果返回成功数与错误列表。
   - 每次同步记录最后时间、状态和摘要。

3. **自动发送安全**
   - 自动发送默认关闭。
   - 启用前可看到到期数量、今日预计发送数量和最早逾期日期。
   - 后台调度只处理 Email，继续受日额度、单批限制、无效邮箱和退订规则保护。
   - WhatsApp、Instagram、Facebook 保持人工触发。

4. **每日就绪中心**
   - 首页展示邮箱配置、回复同步、逾期序列、客户邮箱质量和自动发送状态。
   - 状态分为：正常、需处理、阻塞。
   - 每项状态给出可执行建议和跳转目标。

5. **显式错误反馈**
   - 首页额度、序列、商机和分析接口失败时显示错误，不再静默吞掉。

### 验收标准

- API 返回和更新联系人职位的自动测试通过。
- 两个邮箱的模拟回复可以在一次同步中合并入库；一个邮箱失败时另一个仍成功。
- 新数据库的自动发送为关闭状态。
- 自动发送预览不会产生发送记录。
- 就绪接口不返回密码等敏感字段。
- 后端全量测试、前端构建和浏览器核心流程通过。

## 5. Wave P — 公司、联系人与任务工作流

### 公司与联系人

- 将公司和联系人拆分：一家公司可以有多个联系人。
- 联系人字段：姓名、职位、部门、决策角色、邮箱、电话、WhatsApp、LinkedIn、语言、时区、首选渠道。
- 自动标记决策角色：Owner、Purchasing、Sales、Project、Technical、Unknown。
- 公司详情显示联系人列表和“最佳联系人”推荐。

### 销售任务

- 独立任务对象：负责人、截止时间、类型、优先级、关联客户/联系人/商机、完成状态。
- 首页“今日任务”按逾期、今日、高价值商机排序。
- 回复、报价发送、商机阶段变化可以自动建议下一任务，但由销售确认。

### 验收标准

- 一家公司可维护多个联系人且触达记录不混淆。
- 每个开放商机必须有下一步行动和截止时间。
- 首页可以在 60 秒内完成“找到今日重点 → 打开客户 → 完成任务”。

## 6. Wave Q — 报价到订单闭环

- 正式报价对象：报价编号、客户、联系人、商机、币种、贸易条款、有效期、产品明细、备件、运费、付款条款。
- LED 专业配置：屏体尺寸、像素间距、箱体尺寸、模组、亮度、刷新率、防护等级、控制系统、备件比例。
- 自动计算面积、分辨率、箱体/模组数量、功耗、重量和金额，并允许人工校正。
- 报价版本管理：Draft、Sent、Viewed、Revised、Accepted、Expired、Lost。
- 报价接受后转为订单；订单记录定金、尾款、生产、验货、出货和交付节点。
- PDF/Excel 输出使用公司品牌模板，并完整关联商机。

### 验收标准

- 一个商机可创建多个报价版本，但只有一个当前版本。
- 报价关键计算有单元测试和边界测试。
- 报价接受后可一键生成订单且不重复录入客户与产品数据。

## 7. Wave R — 评分、漏斗与销售分析

- **客户评分：** ICP 契合度、联系人质量、意向信号、触达行为、数据完整度、时效性。
- **评分解释：** 显示加减分原因，禁止只有不可解释的总分。
- **下一最佳动作：** 基于阶段、回复、报价、任务和时区推荐下一动作。
- **漏斗分析：** 发现 → 有联系人 → 已验证 → 已触达 → 已回复 → 商机 → 报价 → 订单。
- **渠道与话术分析：** 按国家、客户类型、联系人职位、渠道、序列、模板统计回复率和商机率。
- **数据质量：** 重复率、无效邮箱率、职位覆盖率、超期任务率、回复同步健康度。

### 验收标准

- 任一评分可解释其来源。
- 报表分母明确，并可下钻到客户明细。
- 首页建议能减少无效触达，而不是只增加发送量。

## 8. Wave S — LED 行业信号与个性化开发

- 信号来源：官网项目页、招聘、展会参展、经销品牌、政府/场馆项目、中标公告、社交媒体项目发布、新办公地址和合作伙伴变化。
- 信号结构：类型、来源 URL、发生时间、可信度、关联公司、适用产品、建议切入点。
- LED 意图分类：Rental、Fixed Installation、DOOH、Retail、Sports、Church、Control Room、Broadcast、Virtual Production。
- 基于信号生成“为什么现在联系”的开发理由，禁止无依据个性化。
- 信号进入客户时间线，并可创建任务、商机或加入专题序列。

### 验收标准

- 每条信号必须保留来源和抓取时间。
- 低可信信号不会自动触发发送。
- 个性化内容能回溯到具体证据，销售可在发送前审核。

## 9. 实施顺序与发布门槛

| Wave | 业务价值 | 前置条件 | 发布门槛 |
|---|---|---|---|
| O | 保证系统可信、发送安全 | 当前系统 | 全量测试 + 浏览器验收 |
| P | 建立日常销售工作流 | O 稳定 | 数据迁移 + 核心任务流程验收 |
| Q | 把商机转成报价和订单 | P 联系人/任务模型 | 金额计算测试 + 文档输出验收 |
| R | 用数据提高转化效率 | P/Q 数据形成 | 指标口径审计 + 下钻校验 |
| S | 建立 LED 行业差异化 | R 基础评分 | 信号真实性抽检 + 人工发送门禁 |

每个 Wave 独立提交、独立验证。上一 Wave 未通过发布门槛，不进入下一 Wave。
