＃ 100 — 空开场白不是扣下一封信的理由

> 编号：按 `AGENTS.md` 新规矩，Claude 取 100 起的偶数。

## Allen 的话（09-04）

> 空 hook 也不要拦，直接用通用 hook。

## 原来会发生什么

`message_guard` 的 impersonal 检查放行两种首封：正文里含着这家公司自己的开场白，
或者它的 `hook` 就是那句刻意标记的通用句（docs/85 R4）。**`hook` 是空的就两种都不是**，
首封被扣下：

```
无名字 + 通用 hook   → 通过
无名字 + 真 hook     → 通过
无名字 + 完全没 hook → 拦下（impersonal）
```

今天库里 0 家客户的 hook 是空的，所以这条今天没有扣下任何一封信。它是一颗定时的哑弹：
一家新客户进来、官网还没读到、或者读了什么都没读出来 —— 那一封信就不会发，**而且不
报错**，只是在 held 里躺着。这套系统的失败一向是这个形状（docs/77、docs/91）。

## R1：空开场白在渲染时就变成那句通用的

`personalize.render` 里 `{hook}` 取不到值时填 `GENERIC_HOOK`，`{hook_ko}` 填
`GENERIC_HOOK_KO`。docs/85 早就备好了这句话，只是从来没有人在这一步用它。

`hook_ko()` 本身**不变**：认不出的句式仍然返回空，不硬译 —— 半句英文混在韩语信里
是另一回事。变的只是空之后拿什么补。

## R2：守卫把「空 hook」和「通用 hook」当成同一件事

因为渲染之后它们就是同一封信。判成两种结果没有道理，而代价是一封本该发出去的信没发。

**没有放宽的那一半**：一家我们查到过真开场白的公司，信里必须写着**它自己**那句话。
光抄那句人人都有的通用句买不到路 —— docs/85 R4 的这条理由没有过期。

## 为什么这不是「为了让批次发出去而放松守卫」

AGENTS.md 写着：一个挡路的守卫要么是错的（在规格里公开改掉），要么是对的（去做它
要求的事）。这里是前者，理由写在上面：这条检查区分的两种情况，在客户收到的信里是
同一封。改的是规则本身，在规格里，不是在测试里。

守卫真正要挡的东西一个字没动：**一封什么都没说的信不发出去。**

## 验收

1. `hook` 为空的客户，渲染出的英文首封含 `GENERIC_HOOK`，韩语首封含 `GENERIC_HOOK_KO`。
2. 同一封信不再被 `message_guard` 拦成 impersonal。
3. `personalize.hook_ko()` 对认不出的句式仍然返回空字符串。
4. 一家有真开场白的公司，正文里只抄通用句 —— 照旧拦下。
