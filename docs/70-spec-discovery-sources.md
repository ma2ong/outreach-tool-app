＃ 70 — 开发渠道是配置，不是代码

## 为什么只有一条渠道

现在的客户开发只有 DuckDuckGo 一条路（`app/search.py`，一个函数）。每加一条渠道都要改代码、
写测试、重新部署——所以三个月过去还是只有一条。

Allen 要的是 Google 地图、Naver、社媒、博客名录。这些不该是四段新代码。

## R1 一个渠道 = 一段配置

每个渠道声明三件事：**去哪里问、怎么读结果、怎么判断这是不是一家公司**。

```
name:      naver
kind:      api            # api / page / browser
enabled:   看有没有配置密钥
query:     模板
extract:   从响应里取域名和公司名的规则
```

加一条渠道是加一段配置。这个形状是从 AutoCLI 借的——它 55 个站点用的是声明式 YAML 适配器，
而不是 55 段代码，这正是它能维护住的原因。

## R2 一条渠道死了，其他照跑

Naver 改版、Google 限流、Instagram 要重新登录——这些都会发生，而且不会同时发生。

每条渠道单独计成功率，单独失败。**一条渠道抛异常，不能让当天的开发一起停**。今天的日报要
写清楚哪条渠道跑了、出了多少、哪条挂了。

## R3 三种取数方式，一种接口

| 方式 | 用在哪 | 代价 |
|---|---|---|
| `api` | Naver API Hub（网页搜索 + 本地商户） | 要密钥，但稳定、免费额度 77.5 万/月 |
| `page` | 公开网页（现有的 jina 抓取） | 免费，会被反爬 |
| `browser` | Instagram / Facebook | 复用现有登录浏览器，最重，最容易被封 |

上层只管"给我这个关键词的公司列表"，不关心底下是哪种。

## R4 密钥只从环境变量读

`NAVER_API_KEY_ID` / `NAVER_API_KEY` 从环境变量取，**不进代码、不进数据库、不进 Git**。
没配置的渠道自动禁用，不报错、不重试——一条没启用的渠道和一条坏掉的渠道，在日报里必须是
两回事。

## R5 所有渠道共用同一条入库路径

不管从哪个渠道来的公司，都走 `discovery.import_candidates`：同样的同行过滤、同样的查重、
同样的[老客户信息回流](68-spec-develop-not-just-send.md)。

渠道只负责"找到候选"，判断和入库的规则只有一份。否则四条渠道会长出四套略微不同的过滤逻辑，
而其中三套会慢慢过时。

## 不做的事

- 不引入 OpenCLI / AutoCLI 作为运行时依赖。它们是给交互式 AI 会话用的，复用**你正在用的
  那个浏览器**的登录态；这个系统在凌晨三点无人值守地跑，你关掉 Chrome 它就断了
- 不做 Google Maps Places API（要绑卡按次计费），等 Allen 决定。韩国那半边已经由
  Naver 지역검색 覆盖：它返回商家名、地址和电话，正是地图搜索的那部分价值，而且免费
- 不做自动生成适配器。先手写四条能用的，再谈自动化

## 验收

1. 加一条新渠道只需要加一段配置
2. 没配 Naver 密钥时，Naver 渠道显示"未启用"而不是"失败"
3. 一条渠道抓取失败，其他渠道当天照常出结果
4. 任何渠道找到的公司，同行照样被滤掉，老客户照样被补充
5. 日报里能看到每条渠道今天出了多少

## 附：Naver 的入口在 2026 年变了

第一次接的时候走的是开发者中心（`developers.naver.com`）申请 Client ID —— **那条路对新应用
已经关闭**。注册时选 `검색` 会报「신규로 등록할 수 없는 API가 선택되었습니다」，用老 Client ID
调用则报 `Scopes are Empty`。

现在的路径是 **Naver Cloud Platform → API Hub**：

| | 旧（已关闭） | 新 |
|---|---|---|
| 入口 | developers.naver.com | Naver Cloud Platform + API Hub 控制台 |
| 密钥 | Client ID / Client Secret | `X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY` |
| 域名 | openapi.naver.com | naverapihub.apigw.ntruss.com |
| 额度 | 25,000/天 | 775,000/月，目前免费 |

购物、图书、专业文献搜索在 2026-07-31 彻底关闭且没有替代；**网页搜索和지역검색保留**。

记在这里是因为下一个人会先找到那些旧教程——网上大部分文档还停在旧入口。

### 但这条路对 Allen 是走不通的

NAVER Cloud Platform 注册要**韩国实名认证**（휴대전화 본인확인）。Allen 在深圳，没有韩国手机号，
也没有外国人登录证。护照认证覆盖的是 naver.com 个人账号，不是云平台的企业实名。

所以主用的韩国渠道是 **`naver-web`：直接读公开搜索结果页**，不需要任何账号。实测一次查询出
11 家真实的韩国 LED 租赁公司（gadgetrental.kr、media-rental.co.kr、koolsound.co.kr…），
噪音（pstatic CDN、navercorp、daum 论坛）全部滤掉。

**能用的渠道胜过更好但打不开的渠道。** API 那两条代码留着并标成 `optional`——哪天账号能开
就直接启用，在那之前日报不会每天提醒一次这扇打不开的门。
