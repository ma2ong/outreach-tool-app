＃ 86 — 界面上要能改得动，坏了要能看得出来

## 从「站在新用户角度重新看一遍」来的

开了一个空库实例，用浏览器实走了一遍。三条结论，Allen 说照着改。

## R1：外发文案要能在界面里改

改之前，`/api/sequences` 只有 POST / enroll / advance / send，`/api/templates` 只有
GET / POST / DELETE。**两个都没有修改接口。界面上改不了外发文案的任何一个字。**

所以改一句话的唯一路径是：改 Python 源码 → 重新播种 → 重启。09-02 这一天为了改文案
来回了七轮，每一轮都要经过 agent。「we build the panels ourselves」这句 Allen 否掉过两次，
如果界面上能改，他三十秒就自己删了。

两件事让这个编辑器安全，而不只是「能用」：

**编辑过的步骤不能被播种覆盖。** `seed()` 每次都删掉重写全部步骤 —— 对仓库拥有的文案
这是对的，对人改过的文案就是错的。`sequence_steps.edited` 标记归属：有一步被改过，
整条序列就归用户，播种器跳过它。编辑器里的「还原为系统文案」把它交还回去。

**保存之前先判，不是发出去之后才判。** `preview` 拿一个**真的报名在这条序列里的客户**
渲染出来，跑的是发送时同一个 `message_guard`。七条限制、价格规则、退出语规则，
在编辑器还开着的时候就给出答案 —— 而不是某天早上一整批安静地卡住。
守卫拒绝的文案**不落库**。

## R2：每条流水线要有产出检查

改之前的每一项检查问的都是「连上了吗」：邮箱、浏览器、模型、今日额度。
**没有一项问「东西出来了吗」**，而这本书产出的每一个失败都是后一种形状：

| 发生了什么 | 界面上显示 | 代价 |
|---|---|---|
| 关注队列的开关条件永远不成立 | 正常 | 上线至今跑过 0 次 |
| 客户开发导入时丢掉 hook | 导入成功 | 645 家被私信队列永久排除 |
| 报名停在已删除的信上 | 状态「进行中」 | 99 家永远不再收到任何信 |
| `browser_installed` 通配符匹配版本号 | 检查通过 | 浏览器实际是坏的 |

09-02 当天，Instagram 已经七天没发出任何东西、Facebook 和 WhatsApp 五天，
而仪表盘顶部是绿色的「自主销售正常」。

**一句话就能抓住全部**：这条渠道产出了什么，上次产出是什么时候。

安静窗口按节奏给：邮件是每天跑的，两天没动就该说；社媒是成批跑的，
周末安静是正常的，五天才算。**关掉的渠道不算失败** —— 安静正是「关掉」的意思。
**从来没跑过的渠道也不算卡住** —— 那是「还没开始」，是另一句话、另一个修法。

## R3：空的时候只说一件事

空库首屏原来是：两个绿色的「正常/运行中」、一份「今天做了什么」的空报告、
一句「合格新客 0/5 未达标」、一条给程序员看的 `缺少 backend/deepseek_key.txt`、
一个红框警报「⚠️ 收信中断」（而收信**从来没开始过**），然后二十个 0。

**整屏没有一句话说先做什么**，而「客户开发」排在 14 个入口的第 12 位。

现在：客户数为 0 时，仪表盘就是一张卡、一个按钮 ——「去找客户 →」。
客户库空着时，六个批量操作收起来，同样只留这一个入口。

**首次启动自动装话术。** 文案随代码发布，仓库里就有，而一个全新安装的
`sequences` 表是 0 行，要用户自己点一个按钮把它装进来 —— 不点，后面每一步都无事可做。
现在只在一本书一条序列都没有的时候装：用户删过或改过的安装，原样不动。

## 还没做的

* 顶部「自主销售正常」这个绿灯反映的是进程活着，不是能力就绪。空库、没连邮箱、
  没有客户的时候它也是绿的。
* 「新建跟进序列」表单建出来的序列不在 `_sequence_for` 的路由名单里，
  **永远不会有客户被路由进去**。建完看起来成功，一个人都收不到。
