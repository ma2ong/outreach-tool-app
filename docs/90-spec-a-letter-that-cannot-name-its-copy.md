＃ 90 — 一封说不出自己是哪一版的信

## 从「深度研究」那一串问题里剩下的那个

FrontierAgent 那套东西里有一条是「**最终结论是否可以核查**」。docs/89 把它用在了
邮箱上。同一把尺子量文案实验，结果更难看：**实验在跑，但七成的信没有记下自己是哪一版。**

```
email  有变体  294 封      email  无变体  624 封
instagram / facebook / whatsapp  无变体  46 封（全部）
```

## 邮件那 605 封不是 bug，是历史；社媒那 46 封是现在还在发生

按日期切一刀，界线是干净的：

| | 最早 | 最晚 | 条数 |
|---|---|---|---|
| 无变体 | 2026-07-21 | **2026-08-27** | 624 |
| 有变体 | **2026-08-28** | 2026-09-02 | 294 |

`sequence_send` 从 08-28 起就一直在写 `variant=sequence_name`，这条路是好的。
无变体的 624 封里 **605 封的 `campaign` 列上明明白白写着序列名**：

```
序列:冷邮件 3 步跟进（英语）  361
序列:冷邮件 3 步跟进（西语）  110
序列:冷邮件 3 步跟进（韩语）   88
序列:冷邮件 3 步跟进（葡语）   46
```

而社媒的 46 封是另一回事：`channel_outreach` 的两个 `log_send` 调用**今天仍然
不传 variant**，每天的社媒队列发出去就是不可测的。

## R1：能从已有列上读出来的，不叫猜

605 封的变体身份不需要推断 —— `variant` 的定义就是序列名，而序列名就写在
`campaign` 上，去掉 `序列:` 前缀即可。这是同一个事实的第二个副本，不是新断言，
docs/45 那条规矩管的是「没有出处的断言」，不是「换一列读同一件事」。

回填只碰 `variant` 一列，只碰 `campaign LIKE '序列:%'` 且 `variant` 为空的行。
**其余 19 封（`email 2026-07-23`、`每日社媒队列`）不回填** —— 那些标签说的是
「哪天群发的」，不是哪一版文案，硬塞进去会造出一个不存在的变体。

回填之后能回答的问题只有一个，但它是现在完全答不了的那个：**docs/76 的分段文案
（08-28 起）比它替换掉的那版（07-21 至 08-27）好还是差。**

## R2：社媒的每一条 DM 也要说得出自己是哪一版

社媒文案不是随手写的：`social_queue._compose` 按 `copy_segments.segment_of(lead)`
选家族，再按 `no % len(family)` 在家族里轮换句子。**这两个数合起来就是变体身份**，
只是从来没被记下来过。

变体名在**排队的时候**写进队列行，不在发送的时候重算。理由是队列可能昨天就排好了，
而 `segment_of` 读的是 lead 的标签 —— 标签改过之后重算会给一封已经发出去的信
贴上它没用过的标签。**记的是当时用的那一版，不是现在会选哪一版。**

## R3：贴上标签不等于能得出结论

这条写在规格里，是因为它最容易被跳过。

全库到今天为止的真人回信是 **4 家公司**。605 封旧文案对 294 封新文案，
回信 3 比 1 —— 任何按这个数字得出的「哪版更好」都是噪声。
`copy_experiments.breakdown` 现在的做法是对的（无变体的行排除在外，
不当成「表现为零的变体」），回填只是让分母诚实，不会让分子变多。

**标签是必要条件，不是充分条件。** 真正卡住结论的是回信量，
而回信量归 docs/89（别把信发给不存在的地址）和后面的深度研究管。
这条规格能给的承诺只有一句：**等回信攒够的那天，历史数据不会是空白的。**

## 验收

1. 一条 `campaign='序列:冷邮件 3 步跟进（英语）'`、`variant` 为空的历史行，
   回填后 `variant='冷邮件 3 步跟进（英语）'`。
2. 一条 `campaign='email 2026-07-23'` 的行**不被回填**，`variant` 仍为空。
3. 已经有 `variant` 的行一个字段都不动。
4. 回填可以重复跑，第二次改动 0 行。
5. 一条社媒 DM 发出后，`send_log.variant` 写着它当时用的文案家族和句子序号。
6. 队列排好之后改了 lead 的标签，发出去的那条记的仍是排队时那一版。

## 回填之后（09-02）

605 行写入，`copy_experiments.breakdown` 第一次能看到全程：

| 变体 | 发出 | 客户 | 回复 |
|---|---|---|---|
| 冷邮件 3 步跟进（英语） | 361 | 159 | 1 |
| 冷邮件 3 步跟进（西语） | 110 | 103 | 0 |
| 冷邮件 3 步跟进（韩语） | 88 | 47 | 0 |
| 冷邮件 3 步跟进（英语·活动租赁） | 77 | 77 | 1 |
| 冷邮件 3 步跟进（英语·中性版） | 76 | 76 | 0 |
| 冷邮件 3 步跟进（英语·固定安装） | 63 | 63 | 0 |
| 冷邮件 3 步跟进（英语·户外为主） | 19 | 19 | 1 |

仍无变体的 65 行是那 19 封日期标签的群发和 46 条历史社媒，按 R1 不动。

两件事值得记下来，都不是「哪版赢了」：

* **旧文案 361 封只覆盖 159 家**（三步跟进都走完了），
  **新文案 258 封覆盖 258 家**（每家才收到第一封）。拿两组的回复率直接比，
  比的是「一封信」对「三封信」，不是文案。
* 回复数是 1、1、1、0、0……——**R3 说的就是这个**。分母诚实了，分子还是噪声。

## 没做的

* **给那 19 封群发行编一个变体名。** 它们的标签是日期，不是文案版本。
* **把回填的行和新行混在一起算显著性。** 见 R3，样本量不支持，
  `breakdown` 报的是原始计数，不报「谁赢了」。
