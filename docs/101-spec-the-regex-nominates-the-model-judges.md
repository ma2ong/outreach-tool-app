## Allen 的话（09-03）

> 做扩大扫描 + 名字判断交给模型。

## 两个病，一个在质量上，一个在覆盖上

**质量。** `decision_maker_radar` 已经跑过 549 次扫描、攒下 270 个候选人，其中
**24 个有邮箱的全部已提升，246 个没邮箱的全部卡在 `new`** —— 有名字没地址就写不了信。
而那 246 条里的名字是这样的：

```
Nationwide Delivery | project manager      ← 服务名
Great Park Live     | Technical Director   ← 场馆名
Outside Sales       | production manager   ← 部门名
Markdown Content    | founder              ← jina 的排版残渣
```

原因在 `_name_from_window`：它找的是「职位行附近最近的一行大写文字」。在一张服务
列表页上，那就是一个服务名。收紧正则试过两轮，两头都不准 —— `Bart McCollum`、
`TOM WILSON` 这种真人被误挡，`Air Sanitizer` 照样放过。

**覆盖。** `_cold_accounts_missing_authority` 的条件是「序列还在跑」。于是一家公司
的序列一结束就掉出队列：

| | |
|---|---|
| 发过信、有官网、库里没有人名 | **428 家** |
| 其中队列今天看得见的（序列在跑） | 129 家 |
| **因为序列结束而永远排不上的** | **299 家** |

而序列结束恰恰不是不需要人名的理由 —— 那正是没人回信的那一批。

## R1：正则提名，模型判断

第一版是把整页交给模型让它自己找人。**两个真实页面都返回空**：一张 about 页有三万
六千字，人名在 6000 字截断之后。

所以分工反过来。正则擅长定位职位行，模型擅长回答「这是不是一个人」：

```
detect_pages（正则，找职位行附近的名字）
   ↓
looks_like_a_person（黑名单，先挡掉明显不是人的，省下模型判错的机会）
   ↓
judge_people（模型，逐行回答 is_person）
```

**模型只能在候选里挑，不能新造一个名字。** 这是 docs/93 那条规矩在这里的形状：
判断可以交给模型，证据必须留在页面上。

真实页面上的效果：

```
gopce.com/about   正则 9 个 → 黑名单去掉 Great Park Live / Outside Sales
                            → 模型确认 7 个真人
ariaav.com        正则 1 个（Nationwide Delivery）→ 黑名单挡掉 → 0（那页确实没写人）
```

## R2：模型漏答的那一行保留，不当成否定

`judge_people` 只删掉模型**明确说不是人**的行。没被提到的 id 原样留下 —— 一个没有
回答的问题不是一个否定的回答，而悄悄删掉一个真人比留下一个可疑的名字更难发现。

模型不可用时整份名单原样返回：少一个判断不是少一封信。

## R3：队列条件从「序列还在跑」换成「还不知道该写给谁」

```
序列还在跑            → 排得上（不变）
发过信 + 没有人名     → 也排得上（新增，299 家）
```

30 天冷却和每轮上限都不动。这不是把扫描量放大，是让排队的对象换成真正缺名字的那批。

## 验收

1. 「Nationwide Delivery」在进模型之前就被挡掉（模型的提示词里看不到它）。
2. 「Air Sanitizer」黑名单挡不住，模型说不是人时被丢掉。
3. 模型漏答的一行仍在结果里。
4. 模型不可用时，结果和纯正则通道一致。
5. 一家序列已结束、发过信、没有人名的公司排得进 `_cold_accounts_missing_authority`。

## 没做的

* **不抬高每轮扫描上限。** 549 次扫描已经跑完一轮，瓶颈从来不是速度，是扫回来的
  东西不能用。先把质量修好，再谈扫得更多 —— 反过来只是更快地生产垃圾。
* **不让模型改写名字。** 它只回答是或不是。名字的写法以页面为准。
* **不猜邮箱。** docs/89 不变。
