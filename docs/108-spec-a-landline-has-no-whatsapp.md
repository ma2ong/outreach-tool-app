＃ 108 — 座机上不会有 WhatsApp，而你点掉的「确定」不该白点

## 弹窗还在弹，但原因换了一个

Allen 手动发 WhatsApp，又是一串「电话号码 +27 12 809 1494 没有注册 WhatsApp」。

[62 号 spec](62-spec-dialable-whatsapp-numbers.md) 那一层已经修好了：今天队列里 10 条，
拨的全是完整国际号（`+1 404 835 2230`、`+27 12 809 1494`），不再是被剥成 10 位的裸号。
所以这次 WhatsApp 说的是实话——**这些号码本身就不是手机号。**

`+27 12` 是南非比勒陀利亚的固话区号；南非手机号是 `+27 6x / 7x / 8x` 开头。今天队列里
另外 9 条全是从美国公司官网抓来的总机。

## 这两件事的代价是不一样的

| | 我们能做的 | 覆盖 |
|---|---|---|
| 号码是座机，而且看得出来 | 不进队列 | 库里 748 个能拨的号，159 个 |
| 号码是座机，但看不出来（北美） | 只能拨一次，然后记住 | 490 个美国 / 加拿大号 |

北美号码里没有座机／手机这个信息——NANP 不按用途分号段，从 `404-835-2230` 看不出它是
前台电话还是某个人的手机。所以 R2 对美国一条都帮不上，美国那 490 个只能靠 R1。

## R1 你亲眼看见的「没注册」，要能按下去

`whatsapp_status` 现在是 **1320 个 NULL、2 个 active、0 个 `none`**。
[59 号 spec](59-spec-whatsapp-number-status.md) 的记录逻辑是全的，但它挂在 Playwright
自动发送那条路上，而 08-28 之后系统一条都没自动发过——Allen 全是自己在 WhatsApp Web 里
发的。每一次弹窗都是一个已经被观察到的事实，点一下「确定」就没了，明天这个号照样排进队列。

队列的每一行加一个动作：**「这个号没 WhatsApp」** → 写 `whatsapp_status='none'`，
并把这一行移出今天的队列。R59 R2 已经在挡了，写进去就够，不需要另外的拦截。

**它和已有的「不发」是两件事，所以是两个按钮。**「不发」说的是今天不发这一条；这一个说的是
关于这个号码的一个事实，永久生效。把它们合成一个，等于让「今天先跳过」把一个客户永久删掉。

**只有 WhatsApp 自己弹的那句话才配按这个键。** 超时、页面没打开、你临时不想发——按 R59 R1，
那些是关于我们这次运行的事，不是关于这个号码的。这一条没法用代码拦住（按钮在人手里），
写在这里是因为它同样是规则。

## R2 看得出是座机的，不进 WhatsApp 队列

一张表，**只写固话号段，正向匹配上才排除**：

| 国家 | 固话（去掉长途 0 之后） | 手机 |
|---|---|---|
| 韩国 82 | `2` / `31`–`64` | `10` `11` `16`–`19` |
| 巴西 55 | 区号 + `2`–`5` | 区号 + `9` |
| 智利 56 | `2`–`8` | `9` |
| 哥伦比亚 57 | `1` `2` `4`–`8` | `3` |
| 秘鲁 51 | `1`–`8` | `9` |
| 南非 27 | `1`–`5` | `6`–`8` |
| 西班牙 34 | `8` `9` | `6` `7` |
| 英国 44 | `1` `2` | `7` |
| 澳大利亚 61 | `2` `3` `7` `8` | `4` |
| 俄罗斯 7 | `3`–`8` | `9` |
| 新西兰 64 | `3` `4` `6` `7` `9` | `2` |
| 芬兰 358 | `1` `2` `3` `9` | `4` `5` |

**方向是「证明是座机才排除」，不是「不像手机就排除」。** 表里没有的国家（美国、加拿大、
墨西哥、阿根廷），以及号段对不上任何一条的号码，照常进队列。这是 62 号 spec 那句
「宁可少一个渠道，也不要把一个能联系的客户标成死的」在这里的另一面：把一个手机号当成座机
踢掉，损失和把好号码标死是一样的，而拨一次座机的成本只是一次弹窗。

出口和免费电话同一个：`dialable_whatsapp` 返回空，这条线索的 WhatsApp 渠道不可用，
`_channel_for` 自己落到 Instagram / Facebook。

**排除时不写 `whatsapp_status`。** 我们证明的是「这个号是座机」，不是「这家公司没有
WhatsApp」——他们的手机号可能明天就补进来了，那时这个渠道要能自己回来。

## 不做的事

- 不给北美号码猜座机还是手机。NANP 里没有这个信息，按区号或前三位去猜就是编（[45 号 spec](45-spec-truthful-lead-facts.md)）
- 不引第三方号码库。表只覆盖库里真实出现过的国家，跟 62 号 spec R3 一个规矩
- 不改库里存的号码。判断是拨号时做的事
- 不因为一个号码是座机就把线索标成联系不上——邮件和 Instagram 还在
- 不批量预检号码（R59「不做的事」，理由没变）

## 验收

1. `+27 12 809 1494` → WhatsApp 渠道不可用，不进队列
2. `+27 82 555 1234` → 照常进队列
3. `+1 404 835 2230` → 照常进队列（判断不出来，就不排除）
4. 被 R2 排除的号码，`whatsapp_status` 仍然是 NULL
5. 队列行上按「这个号没 WhatsApp」→ `whatsapp_status='none'`，该行消失，明天不再出现
6. 按「不发」→ `whatsapp_status` 不变，明天照常可以再排
