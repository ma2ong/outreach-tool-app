# 44 — Agent-Owned Work Queue

## Goal

Sales Tasks must mean work the human actually has to do. Routine research and bounded
no-reply follow-up that the autonomous sales operator can complete safely must be owned
and consumed by the Agent instead of becoming a growing human to-do list.

## Ownership

`activities.work_owner` is additive and defaults to `human`.

- `human`: pricing, quotation terms, payment, delivery, warranty, negotiation, explicit
  manual tasks, customer-reply takeovers, or ambiguous commercial judgement.
- `agent`: traceable routine research generated by Account Brain / Decision Maker Radar,
  plus bounded continuation of an already-started email conversation.

Historic Agent tasks may be reclassified only when exact proposal/task provenance exists.
Titles are never used to infer ownership.

## Autonomous work

The Worker may execute these Account Brain rules without human approval:

- `refresh_icp`: reread the company website and apply evidence-backed ICP classification;
- `find_decision_maker`: run the source-backed Decision Maker Radar;
- `replace_invalid_channel`: reread company-owned pages and repair a dead contact channel
  only from explicit public evidence, then reuse the existing email verifier;
- `verify_company`: replace junk/page-title company names using the existing safe resolver;
- `schedule_followup`: if the lead has already received one or two emails and has not
  replied, reconnect it to step 2 or 3 of the source-controlled EN/KO 3-step sequence.

A safe machine-owned `create_task` proposal is materialized by the Worker even when the
generic `create_task` autonomy setting is `propose`; this exception applies only to
structured internal Agent work. `off` remains authoritative, and human/commercial task
proposals remain pending.

Weak/absent evidence is not invented. The Agent reschedules its own task for a later
retry; it does not transfer routine research to the human queue.

Decision Maker Radar may keep low-confidence candidates for later rescans. A title can
count as authority coverage, but the Agent does not silently set CRM `role=decision_maker`.

## Bounded email continuation

The Agent never invents follow-up copy. It uses only the approved standard three-step
email sequence already shipped with the product:

- one prior email -> queue sequence step 2;
- two prior emails -> queue final step 3;
- three or more prior emails -> no further cold email; schedule website recheck instead;
- social-only history -> do not silently initiate email and call it a follow-up;
- completed/replied/stopped sequence history is never resurrected.

The router only creates sequence ownership. Actual delivery still goes through the
existing email autosend engine and therefore remains subject to its independent enabled
switch, acknowledged-risk gate, bounce circuit breaker, do-not-contact/reply exclusions,
daily quota, batch limit and pacing. WhatsApp/Instagram/Facebook remain outside this
automatic continuation path.

## UI semantics

The Sales Tasks page defaults to `需要我处理`. `Agent处理中` is a separate read-only
operating queue. The sidebar task badge uses human-owned overdue/today counts only.

## Safety boundary

This feature does not add a new direct customer-send path. Email delivery continues
through the existing guarded sequence/autosend system. It does not autonomously set or
promise price, discount, payment terms, Incoterm, delivery date, lead time, warranty, or
formal quotation terms.

## Failure behavior

Live public research is bounded per Worker cycle. One dead website does not block other
accounts. Transient failures are rescheduled in the Agent queue with an audit note.
