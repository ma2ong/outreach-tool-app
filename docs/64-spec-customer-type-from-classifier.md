＃ 64 — 系统知道对方是做什么的，客户类型栏就不该是空的

## 它一直知道，只是没写下来

今天要发的私信长这样：

> Saw the **rental and staging** work you do around Houston…
> Saw the **rental and event production** work on your site…

系统能写出这句话，说明它已经判断过这家公司是做租赁的。而客户库里这批客户的「客户类型」
那一栏是 `—`。

判断确实存下来了，只是存成了机器自己的话：

| 分类器写的 | 数量 |
|---|---|
| `icp:rental` | 191 |
| `icp:signage` | 26 |
| `icp:integrator` | 15 |
| `icp:reseller` | 12 |

`target_fit` 里是同一个判断的另一种写法（`租赁公司 (90)`、`AV集成商 (85)`）。

[60 号 spec](60-spec-customer-list-columns.md) R2.1 把 `icp:` 开头的从客户类型栏里滤掉了，
理由是"分类器的中间产物不是客户类型"。**那条规则对了一半**：`icp:rental` 这串字确实不该
显示给人看，但它承载的事实——这家公司做租赁——正是客户类型这一栏要回答的问题。

## R1 用他的词，不用分类器的词

分类器有自己一套标签，Allen 有自己一套。翻译一次，此后只说他的话：

| 分类器 | 客户类型 |
|---|---|
| `rental`（租赁公司） | 租赁商 |
| `integrator`（AV集成商） | 系统集成商 |
| `signage`（标识/广告牌） | 广告商 |
| `reseller`（经销商） | 代理商 |
| `end-user` | 终端用户 |

`unknown` 不翻译，也不写。**判断不出来就是空的**，填一个"未知"进去只是把空白换了个写法，
还会让筛选器多出一个没意义的选项。

## R2 他标的永远赢，而且不会被复活

只有当这条线索**一个客户类型都没有**时才写入。他标过的，一个字都不动。

更要紧的是反过来那一面：**他删掉的，不能再长回来。** 如果他把某家的「租赁商」去掉了，那是
一个判断——这家不是租赁商。分类器下次再跑，不能因为官网上还是那些词就把它塞回去。

所以推导只在客户类型为空**且这条线索从来没被人动过类型**时发生。做法是留痕：写入推导类型
的同时保留 `icp:` 那个标记，人一旦编辑过类型，就在标记上记一笔，之后不再推导。

## R3 分类器每次分类，顺手把人话也写上

不是只做一次批量补写。`icp.apply_to_lead` 每次分类完，除了写 `target_fit` 和 `icp:` 标记，
按 R1、R2 把客户类型也补上。否则明天新进来的客户又是一栏空白，一个月后还得再补一次。

## 不做的事

- 不从 `brief` 或 `hook` 的文字里再猜一次类型。那些句子是给客户读的，不是分类依据；
  真要提高覆盖，该做的是让更多客户跑一遍分类器，而不是对同一份证据猜第二遍
- 不改 `target_fit`。它带着分数，是排序和门槛用的，跟给人看的类型是两回事
- 不删 `icp:` 标记。它是出处（[45 号 spec](45-spec-truthful-lead-facts.md)），也是 R2 判断
  "推导过没有"的依据

## 验收

1. 一条带 `icp:rental`、没有客户类型的线索 → 客户类型显示「租赁商」
2. 一条带 `icp:rental`、他已标成「工程商」的线索 → 仍然是「工程商」
3. 他把推导出来的类型删掉，再跑一次分类 → 不会长回来
4. `icp:unknown` 或没有 icp 标记的 → 客户类型仍然是空的
5. 客户类型栏里看不到任何 `icp:` 开头的字样
