＃ 63 — 韩国半自动，其他国家全自动

## 为什么韩国要单独一档

[53 号 spec](53-spec-social-dm-autonomy-switch.md) 把「谁按发送」做成了按渠道选：off / 手动 /
全自动。渠道是对的切法，因为风险是账号级的——Instagram 封号不会回来，WhatsApp 那个号上还有
微信和全部客户联系方式。

但风险不只有账号那一层。**韩国那 303 家里，一多半是 Allen 已经做了几年的客户**：小满里
176 家带着他自己打的标签，130 家记着联系人姓名和职位，还有他手打的「(成交客户)」「(已加微信)」。

给一个陌生的美国租赁公司自动发一句开场白，最差的结果是被无视。给一个认识他好几年的韩国
老客户自动发同一句话，对方读到的是「这人拿群发软件给我发广告」——**那不是一次失败的触达，
是一段关系的损耗。**

所以韩国这一档不是技术差别，是关系差别。

## R1 国家只能往回拉，不能往前推

自主程度按 `off < 手动 < 全自动` 排。一条私信实际走哪一档，取的是**渠道设置和国家设置里
更保守的那个**。

这个方向是刻意的：**任何国家都不能让一个 Allen 没打开的渠道自动发信。** 渠道那一层管的是
账号风险，[53 号 spec](53-spec-social-dm-autonomy-switch.md) 要求把它抬到全自动得手动打出
渠道名字。如果国家设置能反过来把渠道推上去，那道确认就等于绕过去了——而
[AGENTS.md](../AGENTS.md) 里那条老规矩说得很清楚：**同一件事的低签名版本，是一件新的、更
危险的事。**

国家能做的只有一件：把某个国家的私信从「自动发」拉回「等我确认」。

## R2 韩国默认手动，其余国家跟随渠道

| | 默认 |
|---|---|
| South Korea / KR | 手动——Agent 备好，Allen 确认后发 |
| 其他国家 | 跟随渠道设置 |
| 国家为空 | 跟随渠道设置 |

国家为空的按「跟随」而不是按「手动」处理：他的名单里国家缺失多数是没抓到，不是韩国。把
未知一律当韩国，等于让他去确认一批本来可以自动发的美国客户，那道确认很快就会变成机械点头，
而机械点头的确认拦不住任何东西。

## R3 改成全自动仍然要他自己说

R2 只改默认值，不改开关。把渠道抬到全自动依旧需要 53 号 spec 那道打字确认，Agent 自己
永远不能抬。

## 不做的事

- 不动邮件。邮件的日上限、退信保护和序列是另一套，本 spec 只管社媒私信
- 不做「按客户」的开关——一家一家配置，最后一定是配了一半就再没人维护
- 不因为一个国家设成手动就把它排除出队列。队列照常备好，只是等他按发送

## 验收

1. 渠道设成全自动、客户在美国 → 到点自动发出
2. 渠道设成全自动、客户在韩国 → 留在队列里等确认，不自动发
3. 渠道设成手动、客户在美国 → 等确认（国家推不动渠道）
4. 客户没有国家 → 跟随渠道
5. 韩国那批仍然出现在「今日社媒私信」列表里，可以一键发
