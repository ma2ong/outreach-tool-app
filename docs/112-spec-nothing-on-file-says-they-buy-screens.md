＃ 112 — 库里没有一个字说他们买屏

## 两家公司，两种问题

**EKM Exports（#1337）** —— 南非农产品出口商。2026-08-26 从小满 CRM 导入（2023-04-28 有过
两封邮件往来），08-30 发了开发邮件，09-08 发了 FB 私信。

它的开场白是系统自己从官网读出来写的：

> You export roughly 3 million cartons of produce annually.

**我们读懂了这家是干什么的，然后拿这句话去写了一封 LED 开发信。** 结论就在记录上，
没有任何一段代码用它问过「这家该不该在库里」。

**Amos Productions（#647）** —— 湾区活动公司。Allen 看它的 Facebook：酒庄舞会、80 年代金曲夜、
DJ。而它自己的官网写着 `Full-service AV production; LED video walls, live sound, lighting, DJ`，
`business` 字段里存的就是这句，分级判成租赁公司 96 分。

**这两家不是一个问题。** 第二家在文字上就是这一行的——判它不是买家，靠的是它社媒上在发什么，
那是人的判断，这份规格不假装能做。它只做第一种：**库里关于这家公司的全部文字里，
没有一个字跟这门生意有关。**

## R1 「看不出」是一个结论，要写在记录上

`icp.apply_to_lead` 现在遇到 `unknown` 直接 return，什么都不写。于是「读过官网，看不出是
这一行的」和「从没分过级」在库里长得一模一样——两者都是空的 `target_fit`。

判不出来时写 `target_fit='未知 (0)'` 和标签 `icp:unknown`。
[docs/64 R3](64-spec-customer-type-from-classifier.md) 已经立过同一条：结论只活在一个没人读的机器标签里，
等于没有结论。

## R2 「没有行业证据」是一个可判定的状态

把这家公司在库里的全部文字接起来——公司名、简介、开场白、业务、官网域名、标签、客户类别——
里面有没有出现过这门生意的词：led / display / screen / panel / video wall / signage /
billboard / rental / staging / event / 展会 / 전광판 / pantalla / painel / 显示屏 ……

一个都没有，就是「没有行业证据」。注意客户类别本身也算证据：判成「租赁公司 (90)」的公司，
它的类别标签里就写着这一行。所以这条规则只有一句话：**我们手里没有任何一句话说这家跟屏有关。**

它不是「这家不是客户」的证明，是「我们不知道这家是不是客户」的证明。两者的处置不同：
前者该删，后者该问。

**判之前得先有话可判。** 简介 + 开场白 + 业务加起来不到 40 个字的，是「还没看过这家」，
不是「看过了看不出」—— 把这两件事混成一个结论，正是 R1 要修的那个毛病，不能在这里又犯一次。
刚采集进来、官网还没读到的公司照旧走原来的路。EKM 那条有 115 个字：一句官网原话加两封
邮件的往来记录，够判了。

## R3 没有行业证据的客户，不进当天的自动发送队列

每日社媒队列和自动邮件补位跳过它们。AGENTS.md 那句在这里逐字适用：
**不确定是停下来问的理由，不是猜的理由。**

只挡自动的两条路。手动群发和手动私信是 Allen 自己点的，他知道自己在发给谁。

## R4 客户库体检列出来，附上我们手里的全部文字

新增一项「看不出跟显示屏这一行有关」，每条都带着那句原文——EKM 那一条会显示
「You export roughly 3 million cartons of produce annually」，一眼就能判。

一键动作是**标为不再联系**，不是删除：这类记录常常有真实的往来历史（EKM 有两封 2023 年的邮件），
删掉就没了，而不再联系可以一键撤销。

## R5 今天这张名单是空的，这条规则是给下一个 EKM 用的

写这份规格时库里 1310 家活跃客户，没有一家命中——EKM 已经被 Allen 手工删掉了，
其余 674 家没有客户类别的客户，简介里全都写着 LED、面板、租赁。

**空名单不等于没用。** 这条路是从小满导入进来的：一家没有官网、只有两封旧邮件的公司，
在网站被读到之前谁也看不出它是干什么的；等读到了，结论必须有人接住。
